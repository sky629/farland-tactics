# 파랜드 택틱스 2 웹 리메이크 — 사용 설명서

이 문서는 원본 게임 데이터를 푸는 방법, 웹 자산으로 변환하는 방법, 뷰어와 분석 도구를 쓰는 방법을 설명한다. 설계 근거는 `docs/superpowers/specs/2026-10-14-rendering-foundation-design.md`에 있다. 파일 포맷은 `analysis/file_formats.md`에 있다.

## 1. 개요

### 1.1 프로젝트

- 원작: 파랜드 택틱스 2(FT2.exe, 1998). TGL의 Farland Saga 時の道標 한국어판. 640×480, 256색.
- 목표: 원본 데이터 파일을 그대로 읽어 브라우저에서 원작과 같게 그린다. 원작의 특이한 동작(예: 뒤집힌 회피 판정)도 그대로 둔다.
- 방식: Python이 원본 바이트를 풀어 PNG와 JSON으로 쓴다. TypeScript가 그 의미를 해석한다(애니메이션 스크립트 컴파일, 색 키, 그리기 순서).

### 1.2 진행 상태

| 하위 프로젝트 | 내용 | 상태 |
|---|---|---|
| 1 렌더링 기반 | 자산 변환, 맵·스프라이트 그리기, 애니메이션 재생, 개발용 뷰어 | 완료 |
| 2 전투 1판 | 유닛 배치·이동, 공격·마법 판정, 적 AI, 승패 (33개 전투 선택) | 완료 |
| 3 아이템·소지품 | 전투 중 아이템 사용, 보물 습득, 파티 소지품·장비 가방, 장비·상점 규칙 | 완료 (상점·장비 화면은 4에서) |
| 4 스크립트 VM | 이벤트 스크립트 실행, 대화, 마을, 상점, 스테이지 진행(`play.html`, §7) | 완료 |
| 5 세이브·소리·비주얼 씬 | 원작 세이브 호환, WAV/MIDI, 비주얼 씬 (§7.6–7.8) | 완료 |
| 6 완결성·충실도 | 디졸브·크레딧·스태프 롤·오프닝 등장인물, 보류 지적, 처음부터 끝까지 자동 진행 테스트 (§7.10) | 완료 |
| 7 원작 UI 재현 | 게임 창 안의 메뉴 바·팝업·대화상자 21개(FT2.exe 자원에서 생성), 옆 패널은 개발용 (§7.2) | 완료 |

### 1.3 데이터 정책

- 원본 게임 파일(`*.egg`, `extracted/`)은 저장소에 넣지 않는다. `.gitignore`가 이 경로를 막는다.
- 변환 결과(`web/public/assets/`, 약 71 MB)는 받은 사람이 바로 실행할 수 있도록 저장소에 들어 있다(2026-10-22부터). 원작의 그림·지도·음악·대사는 원 저작권자의 것이며, 권리자의 요청이 있으면 내린다. 개발자의 세이브 파일(`assets/save/`)만 제외한다.
- 자료는 `tools/ft2_setup.py` 로 원작 파일에서 다시 만들 수 있다(§3).

## 3. 설치

1. 저장소를 받는다. 모든 명령은 저장소 루트에서 실행한다. `web/` 안에서 실행하는 npm 명령만 예외다.
2. 웹 패키지의 의존성을 설치한다. 변환 자료가 저장소에 들어 있으므로, 이것으로 설치는 끝이다(§5의 `npm run dev` 로 실행).

```bash
cd web && npm install && cd ..
```

설치하는 패키지는 개발용 `typescript`, `vite`, `vitest`, `@types/node` 와 MIDI 합성용 `spessasynth_lib`, `spessasynth_core` 다.

자료를 원작 파일에서 다시 만들어야 할 때(§4의 과정 전체)는 설치 도구 한 번으로 끝낸다. 추출 → 변환 → 사운드폰트 → `npm install` 을 차례로 실행하고, 이미 있는 단계는 건너뛴다.

```bash
python3 -I tools/ft2_setup.py /경로/파랜드택틱스2.vol1.egg        # .egg 한 권(어느 권이든) 또는 그 폴더
python3 -I tools/ft2_setup.py extracted/FarlandTactics2 --force  # 설치된 게임 폴더에서 자료를 다시 내보낸다
python3 -I tools/ft2_setup.py --run                              # 저장소 루트의 .egg 를 쓰고, 끝나면 npm run dev
```

## 4. 원본 데이터 준비

### 4.1 EGG 아카이브 풀기

원본은 ALZip EGG 형식의 분할 아카이브 18개다(암호 없음, 비솔리드). `tools/ft2_unegg.py`가 이 아카이브를 푼다.

1. 18개 `.egg` 파일을 저장소 루트에 둔다. 파일 이름을 바꾸지 않는다. 도구는 `.vol1.egg`의 이름으로 나머지 볼륨을 찾는다.
2. 내용을 확인한다.

```bash
python3 -I tools/ft2_unegg.py 파랜드택틱스2.vol1.egg
```

마지막 줄이 다음과 같아야 한다.

```
files: 5323, dirs: 0, total: 231,579,138 bytes, unparsed tail: 0 bytes
```

3. 아카이브를 푼다.

```bash
python3 -I tools/ft2_unegg.py 파랜드택틱스2.vol1.egg extracted
```

4. 아카이브는 `FarlandTactics2_Package.vol1` ~ `vol6` 여섯 폴더를 담고 있다. **vol1 폴더만 전체 1,704개 파일을 담는다.** vol2~vol6은 파일 일부만 담은 부분 사본이다(세이브 파일 3개만 내용이 다르다). vol1을 작업 폴더로 옮기고 나머지는 지운다.

```bash
mv extracted/FarlandTactics2_Package.vol1 extracted/FarlandTactics2
rm -r extracted/FarlandTactics2_Package.vol{2,3,4,5,6}
```

설치된 게임 폴더(`FT2.exe`가 있는 폴더)가 이미 있으면 그 폴더를 `extracted/FarlandTactics2`로 복사한다. 단계 2~4는 건너뛴다.

### 4.2 게임 폴더 구조

```
extracted/FarlandTactics2/
  FT2.exe        원본 실행 파일. 역공학 대상
  Map/           맵 76개 (stageNN.map) + 비트맵 213개 (배경 stNNa, 레이어 stNNb.., cloud/rain/snow)
  Sprite/        스프라이트 312개 (*.APD) + 시트 비트맵 418개
  DATA/          테이블 *.dat (race, item, magic, stage, desc), 이벤트 스크립트 EVENT*.dat
  bmp/           UI 비트맵 (얼굴, 창, 아이콘). 하위 프로젝트 5에서 쓴다
  Midi/ Wave/    음악 51곡, 효과음 107개. 하위 프로젝트 5에서 쓴다
  Save/          세이브 32개. 하위 프로젝트 5에서 쓴다
```

모든 `.bmp`와 `.map` 파일은 SZDD(MS-DOS COMPRESS) 압축이다. 도구가 읽을 때 자동으로 푼다. 사용자가 미리 풀 필요는 없다.

## 5. 웹 자산 변환

### 5.1 실행

```bash
python3 -I tools/ft2_export.py extracted/FarlandTactics2 web/public/assets
```

약 20초 걸린다. 끝나면 다음과 같이 출력한다.

```
maps 76, sprites 312, pngs 631, warnings 4, errors 0
warning: stage90.map: background st90a.bmp not found
warning: CHAR_29Z.APD: sheet char_29d.bmp not found
warning: breath_4.APD: sheet tornado.bmp not found
warning: char_11e.APD: sheet char_11e.bmp not found
```

경고 4개는 원본 배포판에 없는 파일이다. 변환기는 참조 이름을 JSON에 그대로 쓰고 PNG만 건너뛴다. 이 경고는 정상이다.

| 결과 | 종료 코드 | 뜻 |
|---|---|---|
| `errors 0` | 0 | 성공. 경고가 있어도 0이다 |
| `errors N` (N > 0) | 1 | 파서 검증 실패(이미지 RECT가 시트 밖, 패턴 번호 범위 밖 등). 메시지의 파일 이름을 확인한다 |

### 5.2 출력 구조

```
web/public/assets/
  index.json              { format: 1, maps: [76개 이름], sprites: [312개 이름] }
  map/stage02.json        맵: 크기, 배경·레이어 이름, 셀(높이, blocked, flag2, land, 오브젝트)
  map/st02a.png ...       배경과 레이어 이미지
  sprite/char_01a.json    APD: 시트 이름, 이미지, 패턴, 애니메이션 이름과 스크립트 원문
  sprite/char_01a.png ... 시트 이미지
```

- 모든 이름은 소문자 stem이다. 원본 `CHAR_01a.APD` → `char_01a`. 원본 `St02A.BMP` → `st02a`.
- PNG는 8비트 인덱스 PNG다. 팔레트 256색을 그대로 보존하고 투명(`tRNS`)이 없다. 투명은 렌더러가 색 키로 처리한다.
- 변환기 또는 파서(`tools/ft2_*.py`)를 바꾼 뒤에는 변환을 다시 실행한다. 출력은 덮어쓴다.

## 6. 전투 페이지

```bash
cd web && npm run dev
```

브라우저에서 http://localhost:5173/game.html 을 연다.

### 6.1 시작

1. **전투** 목록에서 하나를 고른다(33개, `번호 에피소드 — 목표`). 첫 항목이 원작의 첫 전투 "첫업무"다.
2. **시드**는 비워 두면 시각으로 정한다. 같은 시드와 같은 조작은 같은 결과를 낸다.
3. **시작**을 누른다. 파티는 새 게임 파티(카린·알, 로스터 1의 장비)에 고른 전투의 로스터를 적용한 것이다. 파티 레벨이 로스터보다 낮으면 로스터 레벨까지 올린다. 로스터가 (0, 0)에 둔 유닛은 이야기 스크립트가 배치하던 것이라, 파티원은 배치된 파티 옆에 둔다(리메이크 편의 규칙). (0, 0)에 숨어 있는 적(status 9: 엘비스의 천사들)은 그대로 두며, 천사소환이 시전자 주위 8칸 안의 빈 셀에 세운다.

### 6.2 조작

| 조작 | 동작 |
|---|---|
| 아군 유닛 클릭 | 선택. 이동 가능 셀(MOVE 타일)과 메뉴가 나온다 |
| 이동 → 셀 클릭 | 경로를 따라 달린다. 이동은 되돌릴 수 없다 |
| 공격 → 빨간 셀의 적 클릭 | 공격. 숫자 팝업과 로그 |
| 마법 → 주문 → 셀 클릭 | 시전. MP가 부족한 주문은 비활성. 전체 범위 주문(사이렌즈 등)은 시전자 칸에 표시된 한 타일을 클릭해 확정한다 |
| 아이템 → 항목 → 셀 클릭 | 소지한 소모품을 자신 또는 인접 아군에게 쓴다. 하나가 소비된다. 사용할 수 있는 소모품이 없으면 비활성 |
| 대기 | 유닛 종료 |
| 방향 화살표 클릭 / 유닛 클릭 / Enter | 행동 뒤 바라볼 방향. 배후·측면 판정에 쓰인다 |
| 오른쪽 클릭 / Esc | 한 단계 취소 |
| 턴 종료 | 적 페이즈. 모든 아군이 끝나도 자동으로 넘어간다 |
| 방향키·드래그·Shift | 뷰어와 같다 |

### 6.3 규칙 요약

- 유닛마다 턴에 이동 1회, 행동 1회. 이동력 30, 지형 비용은 종족표. 다른 유닛이 선 칸은 지나가지 못하고, 적 옆 칸에 들어가면 멈춘다(ZOC).
- 명중·크리티컬·회피는 민첩 비율, 방향(배후 ×2, 측면 +50 %), 상태로 정한다. 대미지 = 공격 − 방어, 속성·배율·높이 보정. 자세한 공식은 `analysis/battle_rules.md`.
- 적은 원작 AI 점수표로 움직인다(`analysis/field_mode.md` §5).
- 적 전멸 → 승리, 아군 전멸 → 게임 오버. 결과는 패널에 뜬다.

### 6.4 없는 것

이 페이지는 전투 엔진의 시험대라서 이야기·대사, 마을·상점·장비 교체 화면, 세이브, 소리가 없다. 모두 플레이 페이지(§7)에 있다.

### 6.5 보물과 소지품

- 보물(상자 오브젝트)이 있는 칸으로 이동하면 바로 줍는다. 골드는 파티 골드에, 소모품은 파티 소지품에, 장비는 그 유닛의 장비 가방(4칸)에 들어간다. 가방이 가득 차면 "더 가질 수 없다"가 뜨고 보물은 남는다.
- 숨은 보물은 파티 유닛이 인접하면 드러난다("보물 찾았다!").
- 패널의 소지품 절에 골드, 소모품(이름 ×개수), 파티원별 가방이 보인다.
- 전투 페이지는 시작 키트(골드 300, 허브 3, 해독초 2, 깨어나는 약 1)로 시작한다. 이것은 개발 페이지의 편의 기능이다. 실제 게임에서는 이야기 스크립트가 아이템을 준다.
- 장비 교체와 상점은 규칙만 구현되어 있다(`web/src/battle/equipment.ts`, `shop.ts`). 화면은 하위 프로젝트 4(마을·상태 화면)에서 붙는다.

## 7. 이야기 모드 (플레이 페이지)

```bash
cd web && npm run dev
```

브라우저에서 http://localhost:5173/play.html 을 연다. 원작 이벤트 스크립트(`EVENT00.DAT`…)가 게임을 처음부터 이끈다: 로고 → 오프닝 → 마을 → 시설 → 전투 → 다음 스테이지.

### 7.1 시작

1. 타이틀 그림 위에 원작처럼 **데이터 선택**(143)이 바로 뜬다(원작은 stage 0 의 필드 프레임이 `FUN_004239b0(-1)` 로 연다). **처음부터**가 새 게임이다: 소지금 200, 턴 −1(마을)에서 `EVENT00` 의 `begin` 라벨이 실행된다. 슬롯을 골라 **결정**하면 이어서 한다(§7.6). **취소**하면 타이틀 그림만 남고, 클릭이나 Enter 로 대화상자가 다시 뜬다 [추정]. 원작 EXE 의 **스테이지 선택**(124)은 INI `CompleteFlag` + Shift 로만 여는 디버그 대화상자라 쓰지 않는다.
2. 로고 3장(각 4초)과 오프닝 대사가 이어진다. 대사는 **클릭** 또는 **Enter** 로 넘긴다. 클릭 1번이 대사 1번이다(연타해도 건너뛰지 않는다).
3. 화면은 원작 창 그대로다: 위에 메뉴 바(`맵` → 표시·턴 종료·시스템), 아래에 640×480 화면. 둘이 같은 정수 배율로 커진다. 개발용 옆 패널(로그·유닛 수치·오류)은 `play.html?dev=1` 에서만 보인다. 전투 테스트 페이지(`game.html`)는 §6 그대로 패널을 쓴다.

### 7.2 조작

| 장면 | 조작 | 동작 |
|---|---|---|
| 대사 | 캔버스·대화창 클릭, Enter | 다음 대사 (`WAIT_CLICK`) |
| 메시지·질문 | 닫기 / 예 / 아니오 | 모달을 닫고 스크립트가 이어진다 |
| 마을 | 시설 위에 마우스 | 커서가 손 모양이 되고 하이라이트가 켜진다 (활성 시설만) |

### 7.3 마을

- 배경은 원작 `Town%02d.bmp` 레이어다. 낮/밤/어둠 세트는 스크립트가 고르고, 프레임 시트(깃발·물결·창문 불빛)는 50 ms 틱으로 움직인다.
- 시설은 15개(§`analysis/story_flow.md` 3.2). 스크립트가 `TOWN_FLAG_SET` 으로 켠 시설만 반응한다. 첫 마을에서는 여관과 길드가 열려 있다.
- 오른쪽 클릭 → 원작 팝업(`FUN_0042b620`): **이동하다** ▸ 지금 열린 시설 이름들(클릭 대신 쓴다), **갈 수 있는 장소 표시**(하이라이트 전체 토글), **유니트 일람**, **전 화면 표시**, **시스템** ▸ 불러오기·저장하기·환경설정·게임종료.
- **유니트 일람**(F2, 대화상자 107): 왼쪽에 파티원, 오른쪽에 탭 **능력**(이름·종족·레벨·체력·마력·공격력·방어력·지력·마항력·민첩성·속성·경험치) · **장비**(무기·소지물·방패·장비1·장비2 — 엔진의 무기·가방·방어구·장신구 1·2 에 대응 [추정]; 더블클릭 → 장비하다 / %d에 판다, 입은 것은 오른쪽 클릭 → 벗는다) · **마법**(명칭·마력) · **도구**(명칭·갯수; 오른쪽 클릭 → **팔기** → "몇개 팔았습니까?"(153)로 개수를 정해 반값에 판다). 상점에서 열면 **매각** 탭(118)이 더 있다. 탭의 **이동** 버튼(원작: 그 유닛으로 화면 스크롤, `FUN_0042dc70`)은 전투 중에만 켜지고(원작도 모드 1 에서만 활성) 누르거나 파티원을 **더블클릭**하면 그 유닛이 화면 가운데 오고 대화상자가 닫힌다. **능력** 탭의 그림 자리에는 그 파티원의 얼굴 그림(`face%02da.bmp`, 대사창과 같은 그림 [추정: 첫 표정])이 들어가고, **경험치 배분**(162)의 왼쪽 단추들도 같은 얼굴이다.

### 7.4 전투와 스크립트 훅

- 스크립트의 `BATTLE_START` 가 §6 의 전투를 그 자리에서 시작한다. 파티·소지품은 이야기 전체에서 이어진다(상점에서 산 물건, 전투에서 얻은 경험치).
- 전투 중 원작 훅이 돈다: 행동 직전 `battle%02d`(대사 뒤 행동 수행), 대상마다 `BEAT`/`AFTER`/`ASSIST` 또는 `WIN`, 레벨업 `levelup%02d`, 승리 `COMPLETE`, 패배 `GAMEOVER`. 라벨이 없는 승패는 화면에 아무것도 띄우지 않는다(개발 패널 `?dev=1` 에만 결과가 보인다).
- 이름 있는 적(마크도갈·베히모스 등)의 시체는 스크립트가 치울 때까지 남는다(원작 규칙). 정해진 유닛만 쓰러뜨릴 수 있는 보스(듀마·앨비스: 알의 마지막 일격)는 다른 유닛이 쓰러뜨리면 1 HP 로 다시 선다(`TEST_IS_ACTOR`).
- `BATTLE_START` 는 쓰러진 파티원을 HP 1 로 다시 세우고 상태·버프를 지운다. `BATTLE_START_HEAL` 은 먼저 전원(쓰러진 유닛 포함)의 HP 를 채우고 MP 를 절반으로 맞추며 상태를 지운다. HEAL 없이 이어지는 던전 연전(15일째)은 직전 전투가 끝난 HP 로 시작하므로 마지막 적을 쓰러뜨리기 전에 치료해 두어야 한다.

### 7.5 상점과 모달

- `SHOP` 은 원작 대화상자 **물품목록**(150)이다: 명칭·가격·갯수 목록, **사기** 또는 더블클릭 → **몇개 삽니까?**(151, 갯수·소지금·금액) → 장비면 **누가 사나?**(152, 가방이 빈 파티원과 그 소지품) → 구매. 소모품은 공용 소지품에, 장비는 고른 파티원의 가방(4칸)에 들어간다. **유니트 일람**은 §7.3 의 대화상자를 **매각** 탭(118)과 함께 열고, 닫으면 상점으로 돌아온다. 판매는 원작대로 유니트 일람에서 한다: 장비는 **장비** 탭의 **%d에 판다**, 소모품은 **도구**/**매각** 탭의 **팔기** → **몇개 팔았습니까?**(153). 매각가는 구입가의 절반(추정 — 원작 매각가 공식은 미확인).
- `BATTLE_RESULT` 는 **경험치 배분**(162)이다: 파티원마다 막대와 `경험치(+배분)` 표시, 남은 풀, **밸런스 배분**(가장 낮은 유닛부터 채우는 원작 기본 배분, 처음 상태)과 **균등배분**, **결정**을 누르면 경험치가 들어가고 레벨업 목록 메시지가 뜬다. 다 나누지 않고 결정하면 남은 풀은 버려진다 [추정]. 막대는 슬라이더로 대신한다(원작은 직접 그린 막대 [추정]). 경험치 상한은 9899.

### 7.6 저장과 불러오기

- 세이브는 원작과 같은 `save%02d.dat`(6848 바이트)다. 원작 게임이 쓴 세이브를 **불러오기 → 가져오기**로 넣을 수 있고, **내보내기**로 받은 파일을 원작 `save\` 폴더에 넣으면 원작도 읽는다.
- 슬롯은 32개(00~31). 브라우저 저장소(IndexedDB)에 남는다. 사생활 모드처럼 저장소를 못 열면 그 페이지 안에서만 유지되고 안내가 뜬다.
- 자동 저장: 전투 시작 때 슬롯 30, 매 턴이 끝날 때 슬롯 31 (원작과 같다).
- **저장**: 메뉴 `시스템 → 저장하기`(F5) → **데이터 선택**(143)에서 슬롯을 고르고 **결정**(더블클릭도 된다). 행은 원작 형식 `번호: n일째  Turn t  제목`(마을 저장은 `어트랙터`), 빈 슬롯은 `미등록`, 읽을 수 없는 슬롯은 `손상됨`. 찬 슬롯은 바로 덮어쓴다(원작 대화상자에 확인이 없다 [추정]). (원작 스크립트는 슬롯 30 자동 저장만 쓴다.)
- **불러오기**(F1, 타이틀의 불러오기): 같은 대화상자. **처음부터**는 새 게임이다. 대화상자 아래 줄의 **내보내기 · 가져오기… · 삭제**는 웹판이 더한 것이다: 가져오기는 빈 슬롯에 들어가고, 빈 슬롯이 없으면 덮어쓸 슬롯을 묻는다.
- 불러오면 저장된 스테이지의 `Restart` 라벨부터 이어진다(마을이면 마을, 전투 중이면 전투를 다시 세운다). 음악 번호도 되살린다.

### 7.7 소리

- 효과음은 원작 `Wave/*.wav`(107개), 음악은 `Midi/bgm%02d.mid`(25곡, GM 판)을 그대로 쓴다. 변환기(§5)가 `assets/wave`, `assets/midi` 로 복사한다.
- 음악은 브라우저 안의 MIDI 합성기(spessasynth)가 GM 사운드폰트로 연주한다. 사운드폰트는 저장소 밖이라 한 번 받아야 한다:
  ```bash
  python3 -I tools/ft2_soundfont.py web/public/assets     # FluidR3Mono_GM.sf3 (MIT, 약 14 MB) → assets/sf2/gm.sf3
  ```
  없으면 효과음만 나고 **환경설정**(F11)의 안내 칸에 그 사실이 적힌다.
- 브라우저 정책 때문에 소리는 첫 클릭(새 게임·불러오기) 뒤에 켜진다. 그 전에 스크립트가 고른 곡은 기억했다가 켠다.
- **환경설정**(F11, 대화상자 156): 원작대로 **전화면 표시** ON/OFF 와 **효과음** ON/OFF 를 고른다(브라우저에 기억). 대화상자 아래의 **배속** 줄(1배·2배·4배)은 웹판이 더한 것이다(F6 과 같다). 음원은 MIDI 합성기 하나뿐이라 CD-DA 와 DirectX 선택은 회색이다. 음량 슬라이더는 없다(원작에도 없다). 게임을 끝낸 뒤에는 메뉴에 **BGM 선택**(160)이 생겨 25곡을 골라 들을 수 있다. 탭을 숨겼다 돌아오면 음악이 이어진다.
- 원작 규칙: 효과음 채널 16개(`*` 접두 소리는 채널 0 고정), `MUSIC_FADE` 선형 페이드, 같은 곡은 다시 시작하지 않는다 [추정], 반복 재생 [추정]. GS 음원(`_gs.mid`)은 쓰지 않는다.

### 7.8 비주얼 씬

- 스크립트의 `PLAY_VISUAL` 이 부르는 원작 비주얼 씬 11개를 재생한다: 오프닝 무비(새 게임 직후, 18부 약 2분 20초), 이야기 중간의 장면 1·3·4·6·7·9·10·11, 엔딩 두 종(12·13). 원작의 장면 함수를 그대로 옮긴 타임라인(`web/src/visual/scenes/`)으로 그림·애니메이션·이동·페이드·효과음이 원작 시각에 맞춰 나온다.
- **건너뛰기**: 재생 중 화면을 클릭하거나 Enter 를 누르면 장면이 바로 끝나고 스크립트가 이어진다.
- 그림은 변환기가 만든 `assets/bmp/*.png` 와 장면 목록 `assets/data/visual.json`(원작 `vsllst.dat`) 을 쓴다. 변환기를 다시 돌리면 둘 다 갱신된다.
- 오프닝 5·7·9·12·14부의 등장인물은 원작 스프라이트 애니메이션(APD `OP_EVENT1..4`)으로 움직인다. 엔딩 12는 크레딧 그림 일곱 장이 원작 표대로 화면을 가로지르는 동안 `DATA/staff.lst` 의 스태프 롤 글자가 올라간다.
- 엔딩 13의 별 입자(`FUN_00405920` "star")는 원작 루틴을 옮긴 것이다(`web/src/visual/stars.ts`): 별 80개를 20 ms 마다 움직여 원근 투영하고(`bmp\star.bmp` 의 16×16 프레임 8장, 가까울수록 큰 별), 부마다 다른 종류를 쓴다 — 1·4부는 그림 뒤에서 올라오는 별, 3부와 첫 10초는 (300,300) 으로 멀어지는 별, 초상화 부는 (10,400) 기준의 느린 별.
- 근사한 것 [추정]: 디졸브는 투명도 변화로, 엔딩 13의 팔레트 교차 페이드는 컷, 스태프 롤 속도는 33~180 초에 맞춤, 별의 z < 100 프레임은 원작이 그림 밖을 읽는 자리라 가장 큰 별로 고정. 장면 2·5·8 은 어떤 스크립트도 부르지 않아 옮기지 않았다.

### 7.9 알려진 근사와 판정

원작과 다르게 둔 것과 그 이유다. 모두 플레이에는 영향이 없고, 바꾸려면 원작 화면 캡처 같은 근거가 더 필요하다.

- **글꼴·창 크롬**: 대화상자·메뉴는 원작 템플릿 좌표 그대로지만 굴림 비트맵 글꼴 대신 브라우저 글꼴, Win32 창 틀 대신 같은 모양의 HTML 이다. 기능은 같다.
- **시작 환경설정**: 원작은 창을 열기 전에 **파랜드 택틱스 환경설정**(156, 화면 모드·MIDI 장치)을 먼저 띄운다. 웹판은 그 선택이 뜻이 없어 F11 로만 연다.
- **전체 맵**: 원작은 본 창과 별개의 두 번째 창이다. 웹판은 창 하나라 화면 안의 반 크기 자식 창으로 두고, 유닛 표식의 색과 모양은 디컴파일로 복원되지 않아 추정이다(§7.2).
- **경험치 배분**: **결정**을 누르면 남은 경험치는 버린다(원작 처리 미확인). 막대는 원작이 직접 그리는 그림 대신 슬라이더다.
- **얼굴 그림**: 유니트 일람과 경험치 배분의 초상화는 대사창 얼굴 그림의 첫 표정(`a`)을 축소한 것이다. 원작이 어느 표정을 쓰는지는 미확인.
- **엔딩 13**: 팔레트 교차 페이드는 컷, 5부의 마지막 파도 효과는 이름을 알 수 없어 생략. 별 입자는 원작 루틴 그대로다(§7.8).
- **`MOVE_TO`**(오프닝에서 1회: 차여 날아가는 연출)는 애니메이션의 이동 오프셋으로 재현한다. GS 음원(`_gs.mid`)은 원작도 INI `MusicDevice=2` 일 때만 쓰므로 GM 판만 재생한다.
- **세이브 미확인 필드**: 마을 블록 +4(원작 세이브는 1, 웹판은 0)와 하이라이트 플래그 u32[15] 는 뜻을 몰라 0 으로 쓴다. 원작이 읽는 데는 지장이 없다.
- **소리**: 첫 사용자 입력 전의 효과음은 브라우저 자동재생 정책으로 버린다. 기본 음량 80 %.
- **전투 세부**: 회복 숫자는 `POP_` 글꼴(명세의 `B_POP_` 미확인), 적 턴 사이의 300 ms 대기는 턴마다 1회, 독 피해는 로그에만 남는다.
- **맵 69(최종 전투)의 배경**: 배경 그림 `st69a`(768×336)는 맵 자료의 기준점(−320, −240)에 따라 화면 위 336 px 만 덮고, 그 아래는 검다. 그림 크기와 기준점은 원작 자료 그대로지만, 원작 화면에서 아래가 검은지는 미확인이다.
- **스프라이트 레코드 규칙**(2026-10-22, 오프닝 항구 장면에 보이던 "회색 머리 인물" 보고로 복원): 새로 붙인 스프라이트(`ATTACH_SPRITE`·`LOAD_SPRITE`·`SPRITE_REUSE`)는 ANIM 전까지 보이지 않는다(원작 레코드의 애니 번호 −1). `RESPRITE_UNIT`과 `SET_DIR`·`FACE_UNIT`·`WAIT_UNIT` 같은 재구성 시점에 필드 자세를 받고, 스크립트 중 대기하는 파티원의 자세는 SET 이다. 파일에 없는 이름의 ANIM 은 직전 자세를 유지하고, 종족 7 오브젝트에는 자세·그림자·상태 아이콘이 없다(`analysis/field_mode.md` §2.2). 근사로 남긴 것: 재구성하는 EXT 연산의 정확한 집합, 유닛 파일에 걷기 애니메이션이 없을 때 `b` 파일로 대신하는 것, `RESPRITE_UNIT`이 레이어와 표시 상태를 유지하는 것은 [추정]이다.
- **마을에서 시설을 고른 뒤**: 웹판은 마을 그림을 바로 내리고 스크립트의 FADE_OUT(240 ms)을 검은 화면 위에서 돌린다. 원작은 마을 창을 닫고 그 뒤에 남아 있던 필드를 페이드아웃한다.

### 7.10 끝까지 가는지 확인하는 법

`web/test/campaignWalk.test.ts`가 새 게임에서 엔딩까지 헤드리스로 플레이한다. 대사는 클릭하고, 질문은 "예"로 답하고, 마을 시설은 차례로 돈다. 상점에서는 소모품과 두 블레이드(검사, 날개 달린 유닛)의 장비를 사고, 교체한 장비는 판다. 전투 33개는 모두 실제로 둔다. 유닛마다 적 AI의 제안(`chooseAction`)을 받아 플레이어의 규칙으로 고친다.

- 위험 예산: 칸마다 다음 턴에 맞을 기대 피해를 센다(적 각자의 실제 이동+사거리, 근접은 가장 센 네 방, 마법은 MP가 되는 가장 센 주문). 유닛은 체력 여유 안에서만 노출된다(전체 체력의 30 %, 적이 멈춘 뒤에는 15 %). 공격 대상은 그 일격이 쓰러뜨릴 때만 빼고 센다.
- 대형: 가장 오래 버티는 유닛이 앞에서 틈을 막고, 나머지는 그 뒤 두 칸 안에서 싸운다. 적 치유사와 마법사를 먼저 노리고, 뮤트·사이렌즈로 침묵시킨다. 침묵용 MP는 적 치유사가 8칸 안에 있을 때만 남긴다.
- 캐스팅: 공격 주문은 일격과 가치를 비교해 더 나은 쪽을 쓴다. 치유·해독·버프(히트블레이드)는 가치 40 이상이면 먼저 쓴다.
- 물약: 독이면 해독초, 체력이 반 아래면 상처를 덮는 가장 작은 물약을 마신다. 머시룸·에리쿠사(전부 회복)는 마지막 수단이다.
- 되돌리기: 전투에 기여하는 유닛이 쓰러지면 턴 종료 자동 저장(슬롯 31)을 다시 불러 그 턴을 다시 둔다. 한 턴에 3번, 한 전투에 12번, 세 턴 전까지 돌아간다. 쓰러졌던 유닛은 더 조심한다.
- 재시도: 전투에서 지거나 40턴 동안 변화가 없으면 전투 시작 자동 저장(슬롯 30)을 불러 다시 한다. 최대 40번, 매번 다른 태도로 둔다(대담함 ×1, 0.6, 1.6, 0.4, 2.4; 홀수 번째는 전진). 그래도 못 이기면 마을 저장으로 돌아가 마지막 질문의 답을 바꾸거나, 이전 전투로 돌아간다.
- 대본의 끝: 쓰러진 보스가 1 HP로 다시 서면(`TEST_IS_ACTOR`: 듀마와 앨비스는 알의 일격으로만 끝난다) 그 보스를 끝낼 수 있는 다른 블레이드는 난전에서 빠진다. 보스의 주문이 침묵되거나 바닥나면 다가가 마지막 일격을 넣는다.

통과 조건: 18개 스테이지와 전투 33개를 지나 `game complete`가 기록되고, 경고(`warn:`)가 하나도 없어야 한다. 전체 실행은 약 40초다. 실행은 결정적이다: 같은 코드는 같은 재시도 횟수를 낸다.

#### 브라우저 자동 플레이 (렌더링 검증)

헤드리스 워크는 화면을 그리지 않는다. 같은 플레이어 규칙(`web/src/dev/walker.ts`)을 실제 페이지에 붙여 **매 프레임을 그리면서** 끝까지 돌리고, 정해진 순간의 화면을 저장하는 것이 브라우저 자동 플레이다.

1. 개발 서버를 연다: `cd web && npx vite --port 5199 --strictPort`.
2. `http://localhost:5199/play.html?walk=1&seed=7` 을 연다. 페이지가 새 게임을 시작하고 가상 시계(프레임당 1000/60 ms, 기다리지 않음)로 돈다. 자산을 읽는 동안에는 시계가 멈춘다. 소리는 끈다. 세이브는 메모리에만 남는다.
3. 페이지는 그림 요청마다 `window.__walk.pending` 을 두고 멈춘다. 수집기 `tools/walk_browser.mjs`(ego 브라우저의 Node 스크립트: `page.waitForFunction` → `Page.captureScreenshot` → `__walk.resume()`)가 찍고 재개한다. 실행 폴더와 주소를 채워서 넣는다. 수집기 없이 돌리려면 `&shots=0`.

   ```bash
   DIR=/tmp/walk-$(date +%H%M); mkdir -p "$DIR/shots"
   sed -e "s#__RUN_DIR__#$DIR#" -e "s#__WALK_URL__#http://localhost:5199/play.html?walk=1\&seed=7#" tools/walk_browser.mjs > "$DIR/round-01.mjs"
   ego-browser nodejs < "$DIR/round-01.mjs"
   ```
4. 실행을 중간에 멈추려면 그 탭을 닫는다(ego 스크립트는 ego 안의 Node 헬퍼에서 돌아 CLI 프로세스를 죽여도 끝나지 않고, 같은 탭을 두 수집기가 나눠 가지면 사진이 섞인다). 끝나면 `__walk.manifest()` 가 사진 목록·판정 수·로그를 준다. `python3 -I tools/walk_report.py <실행 폴더>` 가 `report.html`(장별 섬네일, 걸린 프레임 먼저)과 `summary.html`(공유용 한 파일)을 만든다.

| 파라미터 | 뜻 |
|---|---|
| `walk=1` | 자동 플레이 모드 |
| `seed=<n>` | 난수 씨앗(기본 7, 헤드리스와 같음) |
| `from=<url>` | 새 게임 대신 그 세이브(전투 시작 자동 저장)에서 시작 |
| `stop=<n>` | 전투 n개를 지나면 멈춤 |
| `shots=0` | 그림 요청에서 멈추지 않음 |

찍는 순간: 맵이 바뀔 때, 전투의 첫 턴·마지막 일격·결과 대화상자, 마을에 들어갈 때, 연출 장면의 부마다, 대화상자가 열릴 때, 10초마다, 그리고 전투마다 한 번 플레이어가 여는 화면(F2 유니트 일람 탭 넷, F3 전체 맵, 오른쪽 클릭 팝업). 자동 판정: 콘솔 오류, 게임 경고(그림 못 읽음 등), 페이드 중이 아닌데 한 색뿐인 프레임(`blank`), 640×480 밖으로 나간 대화상자(`overflow`), 60초(연출 장면은 220초) 동안 변화 없음(`stuck`). 걸린 프레임은 종류마다 장(전투)당 3장까지 찍고 나머지는 센다. `blank` 는 맵·마을·스크립트 그림이 하나도 올라와 있지 않은 프레임은 세지 않는다(세이브를 불러온 직후 Restart 라벨의 `FADE_OUT` 이 돌기 전의 한 프레임, 마을에서 시설을 고른 뒤 맵 없이 도는 페이드아웃). 그런 프레임은 원작 창도 검다. 페이드 또는 검은 색조(`DIM_UI 0` 의 암전)가 화면의 99 % 이상을 덮은 프레임도 덮인 것으로 본다(어두운 장면은 99.5 % 페이드 아래에서 완전한 검정으로 반올림된다). 걸린 사진마다 `note` 에 그 순간의 스크립트 명령(`eventNN@pc`), 페이드 알파, 맵·마을 유무, 카메라 좌표가 붙어서 원인을 바로 읽을 수 있다. `blank` 와 `overflow` 는 사람이 보고 판단한다.

**2026-10-21 실행 결과.** 씨앗 7로 새 게임에서 엔딩까지 돌렸다: 전투 33개, 사진 4,008장, 1,624,208 프레임(가상 7시간 31분, 실제 2시간 15분), 콘솔 오류 0, 게임 경고 0, `overflow` 0, `stuck` 0, 검은 프레임 828개(사진 19장). 이 검증이 찾아서 고친 결함은 세 가지다.

1. 전체 맵 창의 첫 프레임이 맵 조각 하나를 화면에 비추던 것(렌더러가 조각을 화면 밖 캔버스에 그린다).
2. ASK 질문이 대본 원문(`+일을_받아들이겠습니까?`) 그대로 보이던 것(대본 표기를 풀고, `+` 질문은 작은 확인 상자 163에 띄운다).
3. `LOAD_MAP` 뒤에 카메라 명령 없이 페이드인하는 풍경 컷(스테이지 5의 맵 24·17)이 이전 맵의 카메라 위치 때문에 내내 검게 나오던 것(원작의 맵 로드 `FUN_0042d5d0` 처럼 카메라를 맵의 왼쪽 위로 되돌린다).

나머지 `blank` 는 모두 위의 "원작 창도 검은" 프레임이거나, 스크립트가 일부러 비운 화면(`DIM_UI 0` 의 1초 암전, 끝나 가는 페이드아웃)이었다. 보고서 파일은 실행 폴더의 `report.html` 과 `summary.html` 이고, 이 실행의 `summary.html` 은 <https://claude.ai/artifact/79DLy688VorwUyCYpxGhxd> 에, 결함·판정을 정리한 완료 보고는 <https://claude.ai/artifact/ChUjJgi4x9DtHjduVekYrS> 에 올려 두었다(둘 다 비공개 아티팩트).

| 배치 전부 지우기 | 배치한 스프라이트를 모두 지운다 |
| 캔버스 드래그 | 스크롤한다 |
| 방향키 | 16픽셀 스크롤한다. Shift+방향키는 64픽셀 |
| Shift (누르는 동안) | 투시 모드. 앞에 있는 오브젝트를 체크무늬로 그려 뒤의 유닛이 보인다(원작의 Shift 기능) |
| 격자 | 셀 마름모 윤곽을 초록색으로 그린다 |
| 높이 | 높이가 0이 아닌 셀에 높이 값을 적는다 |
| land | 지형 종류(land)별 색으로 셀을 채운다 |
| blocked | 이동 불가 셀을 빨간색으로 채운다 |

(그림 생략: 투시 모드에서 벽 뒤의 캐릭터가 비쳐 보이는 화면.)

### 8.4 상태줄 읽기

```
cell (12, 17) h=2 land=1 blocked=0 flag2=0 objs=1
cam (352, 208)
F.ATTACK6#0/23
```

| 줄 | 뜻 |
|---|---|
| `cell (c, r) …` | 마우스 아래 셀의 대각 좌표 (c, r), 높이 `h`, 지형 `land`, 이동 불가 `blocked`, 미확인 플래그 `flag2`, 오브젝트 수 `objs` |
| `cam (x, y)` | 카메라 왼쪽 위의 맵 픽셀 좌표 |
| `이름#스텝/패턴` | 배치한 스프라이트마다 하나. 애니메이션 이름, 현재 스텝 번호, 현재 패턴 번호 |

### 8.5 좌표계 요약

- 셀 (c, r)의 기준점은 마름모의 중심이다. 화면 x = (c − r)·32 + originX, y = (c + r)·16 + originY − h·8.
- 그리기 순서는 대각 행 s = c + r 오름차순이다. 각 행에서 뒤 오브젝트(front = 0) → 스프라이트 → 앞 오브젝트(front ≠ 0) 순서다. 같은 행의 스프라이트는 배치한 순서다.
- 자세한 근거는 설계 문서 §7에 있다.

## 11. 애니메이션 스크립트 빠른 참조

APD 파일의 각 애니메이션은 ASCII 스크립트다. 뷰어는 이 스크립트를 로드할 때 타임라인으로 컴파일한다(`web/src/sprite/animScript.ts`). 전체 규칙과 원작 함수 근거는 설계 문서 §8에 있다.

| 토큰 | 뜻 |
|---|---|
| `S<ms>` | 이후 프레임의 표시 시간(밀리초). 기본 200 |
| `P<목록>` | 패턴 번호 목록. 각 번호가 프레임 하나 |
| `<a>-<b>` | 범위. 방향은 양쪽 다 가능(`26-29`, `29-26`) |
| `N<n>` | 스텝의 프레임 수. 부족하면 앞 프레임을 돌려 채우고, 많으면 자른다 |
| `M<dx>,<dy>` | 스텝 전체의 이동량(픽셀). 두 번째 수가 스텝을 끝낸다. `M32-16`은 `M32,-16`과 같다 |
| `H`, `V` | 좌우·상하 반전. 숫자 바로 앞이면 그 프레임만, `P`·`M` 앞이면 토큰 전체(`HM`은 dx 부호 반전), `@` 앞이면 포함 전체 |
| `A`~`D` | 숫자 앞에 붙여 그 프레임에 표식 1~4를 단다 |
| `(n)`, `(#n)` | 숫자 앞에 붙여 그 프레임에 트리거 n을 단다. 숫자 하나가 지나면 지워진다 |
| `@<이름>` | 같은 파일의 다른 애니메이션 스텝을 포함한다 |
| 공백, `,` | 구분자. H/V 요소 비트만 지운다. 범위·표식·부호는 다음 숫자까지 남는다 |

예:

| 스크립트 | 결과 |
|---|---|
| `S50 P6 N8 M0,-8` | 패턴 6을 50 ms씩 8프레임. 스텝 끝에 (0, −8)만큼 이동 |
| `S200 P26-29` | 패턴 26, 27, 28, 29를 200 ms씩 |
| `P1-3,2` | 패턴 1, 2, 3, 2 |
| `PA(05)22- 24` | 패턴 22, 23, 24. 표식 A와 트리거 5는 22번 프레임에 붙는다. 공백은 범위를 지우지 않는다 |

스텝에 `P`가 없고 `M`만 있으면 앞 스텝의 프레임을 복사한다. 재생 규칙: 틱마다 프레임 하나씩 진행하고, 스텝이 끝날 때 이동량을 누적한다. 반복 재생은 처음으로 돌아갈 때 누적 이동량을 0으로 되돌린다.

## 12. 코드에서 모듈 쓰기

렌더러는 뷰어 없이도 쓸 수 있다. 다음은 맵 하나와 스프라이트 하나를 그리는 최소 코드다(`web/src/` 기준 경로).

```ts
import { AssetLoader } from './assets/loader';
import { MapModel } from './map/mapModel';
import { ApdModel } from './sprite/apdModel';
import { AnimPlayer } from './sprite/animPlayer';
import { Renderer, type Scene } from './render/renderer';

const loader = new AssetLoader();              // 기본 경로 'assets' (web/public/assets)
const renderer = new Renderer(canvas);         // 640×480 백버퍼를 가진 <canvas>

const mapData = await loader.map('stage02');
const layers = await Promise.all(mapData.layers.map((n) => loader.image('map', n)));
const bg = mapData.bg ? await loader.image('map', mapData.bg) : null;
const map = new MapModel(mapData, layers, bg);
await renderer.prepareMap(map);                // 레이어별 색 키 비트맵을 미리 만든다

const apdData = await loader.apd('char_01a');
const sheets = await Promise.all(apdData.sheets.map((n) => loader.image('sprite', n)));
const apd = new ApdModel('char_01a', apdData, sheets);   // 스크립트를 여기서 컴파일한다
await renderer.prepareApd(apd);

const player = new AnimPlayer(apd.anim('F.SET')!, { loop: true });
const scene: Scene = {
  map, sprites: [{ model: apd, player, c: 12, r: 17 }],
  camera: { x: 0, y: 0 },
  overlay: { grid: false, height: false, land: false, blocked: false },
  seeThrough: false,
};

function frame(now: number): void {
  player.update(now);          // 프레임·이동량 갱신
  renderer.draw(scene);        // 전체를 다시 그린다 (더티 사각형 없음)
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

| 모듈 | 책임 |
|---|---|
| `assets/loader.ts` | 자산을 받아 검증하고 캐시한다. 실패는 `AssetError` |
| `assets/png.ts` | 8비트 인덱스 PNG를 팔레트와 인덱스 배열로 디코드한다 |
| `gfx/indexed.ts` | (이미지, 색 키) → RGBA `ImageBitmap` 캐시 |
| `iso/grid.ts` | 셀 ↔ 화면 좌표, 대각 행 순회, 마름모 피킹 |
| `map/mapModel.ts` | 맵 JSON을 행별 셀 목록으로 바꾸고 레이어 색 키를 정한다 |
| `sprite/animScript.ts` | 스크립트 → `Timeline` 컴파일. 실패는 `AnimScriptError` |
| `sprite/animPlayer.ts` | 시각에 따라 현재 프레임과 누적 이동량을 계산한다 |
| `sprite/apdModel.ts` | 패턴의 이미지 목록, 반전 배치, 그리기 명령 |
| `render/renderer.ts` | 장면을 640×480에 그린다. 투시 모드와 오버레이 포함 |
| `viewer/` | 개발용 뷰어 UI (`main.ts`), 배율·카메라 (`scale.ts`), 시작 순서 (`startup.ts`) |

## 13. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 오류창에 `assets/index.json: HTTP 404` | 자산 변환을 하지 않았다 | §5를 실행한다 |
| 오류창에 `not an asset index (format 1)` | 다른 버전의 변환 결과다 | 변환기를 다시 실행한다 |
| `char_11e`, `char_29z`, `breath_4`를 고르면 `… .png: HTTP 404` | 원본에 시트 파일이 없다(§5.1의 경고 3개) | 정상이다. 다른 스프라이트를 고른다 |
| `stage90`의 배경이 검다 | 원본에 `st90a.bmp`가 없다 | 정상이다 |
| 오류창에 `AnimScriptError: 이름@오프셋: …` | 스크립트 컴파일 실패. 원본 3,065개는 모두 통과하므로 수정한 파일일 때만 생긴다 | 메시지의 애니메이션 이름과 문자 오프셋을 보고 스크립트를 고친다 |
| 코퍼스 테스트가 `skipped` | `web/public/assets/index.json`이 없다 | 변환 뒤 다시 실행한다 |
| `npm install`이 Node 버전 오류를 낸다 | Node 22.12 미만 | Node를 올린다 |
| 화면이 작다 | 창이 작아 1배로 그린다 | 창을 키운다. 배율은 정수만 쓴다 |
| 방향키가 선택 상자를 바꾼다 | 선택 상자에 포커스가 있다 | 캔버스를 한 번 클릭한 뒤 방향키를 쓴다 |
| Shift를 떼도 투시가 남는다 | Shift를 누른 채 창 포커스를 잃었다 | Shift를 한 번 더 누른다 |
| 변환기가 Python 트레이스백을 낸다 | 손상된 원본 파일 | 트레이스백의 파일 이름을 확인한다. §4.1을 다시 한다 |

## 14. 알려진 제한 (하위 프로젝트 1)

- 맵 헤더의 `start` 필드 의미를 확인하지 못했다. 뷰어는 카메라를 맵 중앙에 둔다.
- 같은 대각 행에 놓인 스프라이트끼리는 배치 순서로 그린다. 원작의 정렬 키(+0x48)는 하위 프로젝트 2에서 다룬다.
- 팔레트 애니메이션과 페이드는 없다. 맵 팔레트 재배치(10..121 → 32..143)는 하지 않는다. 색은 같다.
- 스크립트의 트리거와 표식 값은 보존만 한다. 소비자(전투 코드)는 범위 밖이다.
- 원본 배포판에 시트 3개(`char_11e`, `char_29d`, `tornado`)와 배경 1개(`st90a`)가 없다.
- 소리, UI, 전투, 이벤트 스크립트 실행은 뷰어의 범위 밖이다. 모두 플레이 페이지(§7)에 있다.
