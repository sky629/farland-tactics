# 완결성·충실도 (하위 프로젝트 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로드맵 5개 하위 프로젝트가 끝난 뒤 남은 "근사"와 보류 항목을 닫는다: 비주얼 씬의 디졸브·크레딧 그림 슬라이드·스태프 롤 글자·오프닝 등장인물 스프라이트, 사용자 체감이 있는 보류 지적, 문서의 범위 밖 항목 정리.

**Architecture:** 재생기(`visual/player.ts`)에 오브젝트별 알파(`alpha` 명령)와 화면 좌표 스프라이트(`sprite` 명령, 기존 `ApdModel`/`AnimPlayer`), 글자 롤(`textRoll`, 프레임의 `texts`)을 더한다. 변환기가 `DATA/staff.lst` 를 `data/staff.json` 으로 옮긴다. BrowserStage 가 `VisualFrame.texts/sprites` 를 그린다(렌더러에 `drawSpriteAt`, 백드롭 알파).

**Spec:** `docs/superpowers/specs/2026-10-16-save-sound-visual-design.md` §8·§12·§14; `analysis/visual_scenes.md`; 원작 상점 다이얼로그 150 관찰(판매 없음).

- 원작 상점(다이얼로그 150 "물품목록")에는 사기·돌아오기·유니트 일람 버튼만 있다 — 판매는 원작에 없다 [관찰]. 문서에서 "범위 밖"이 아니라 "원작에 없음"으로 적는다.

## Review Focus
1. 알파가 0 인 조각은 그리지 않고, 알파 중인 오브젝트가 애니메이션 프레임을 바꿔도 알파가 이어진다. → Task 1 `alpha ramps and survives a frame change`.
2. 글자 롤은 어떤 프레임에서도 화면 밖 줄을 내보내지 않고, 끝나면 `waitText` 가 통과한다. → Task 2.
3. APD 가 아직 로드되지 않은 스프라이트는 그 프레임만 비고 장면은 계속된다; 로드되면 애니가 처음부터 시작한다. → Task 3.
4. 손상된 세이브 슬롯은 "손상됨"으로 보이고 불러오기가 거부된다. → Task 4.
5. 사운드폰트가 아니라 합성기 자체가 실패해도 안내문이 원인을 말한다. → Task 4.

### Task 1: 오브젝트 알파·디졸브·크레딧 그림

- 커밋 `feat(web): per-object alpha — dissolves and the ending's sliding credit pictures`.

### Task 2: 스태프 롤 글자
- 변환기 `export_staff()` → `data/staff.json` `[{text, size, font:'mincho'|'gotic'}|{space:n}]`; Cmd `textRoll{lines?: from provider, startY: 480, endMs}` + `waitText`; `VisualFrame.texts`; BrowserStage 가 글자를 그린다(흰 글자, 검정 그림자; 명조 = serif, 고딕 = sans). 재생기는 `start(def, part, images, now, texts)` 로 줄을 받는다.
- 테스트: Python `export_staff` 파싱; visualPlayer `the text roll moves up and ends`; scene 12 trace: 40..175 s 에 글자가 있다.
- 커밋 `feat(web): staff roll text in the ending (DATA/staff.lst)`.

### Task 3: 오프닝 등장인물 스프라이트
- Cmd `sprite{id, apd, anim, x, y, times}`; 재생기는 `SpriteProvider` 로 모델을 받아 `AnimPlayer` 를 만든다; `VisualFrame.sprites[{model, player, x, y}]`; renderer `drawSpriteAt(model, player, x, y)`; BrowserStage 는 SpriteCache 를 쓴다. 오프닝 p5(vop06a@(128,120) ×1, vop06b@(320,288) ×1), p7(vop08a@(320,224)), p9(vop10a OP_EVENT1@(288,208), OP_EVENT2@(320,224) ×3), p12(vop13a OP_EVENT1 ×3@(288,272), 2@(352,240), 3@(224,304), 4@(224,240)), p14(vop15a 1@(304,248), 2@(240,248)).
- 테스트: visualPlayer `a sprite plays its anim at a screen point once the model is there`; visualScenes: every sprite's apd/anim exists in the exported sprites.
- 커밋 `feat(web): opening character sprites (APD OP_EVENT anims) in visual scenes`.
