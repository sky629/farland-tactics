# 세이브·소리·비주얼 씬 (FT2.exe)

작성 2026-10-16. 표기: [관찰] = 디컴파일/데이터로 확인, [추정] = 정황. 하위 프로젝트 5 의 근거.

## 1. 세이브 `save\save%02d.dat` [관찰 `FUN_00423820`(쓰기), `FUN_004239b0`(읽기)]

레이아웃은 `file_formats.md` §6. 핵심:

- 쓰기: 헤더 468 B → 유닛 50×124 B(`DAT_0046a880`) → 마을 상태 블록 180 B(`DAT_0044b1b8`, 첫 u32 가 길이). 슬롯 < 0 이면 다이얼로그 0x8F(`LAB_004230b0`)로 슬롯을 고른다.
- 읽기(불러오기): 세 블록을 그대로 메모리에 복사한 뒤 `Restart` 라벨 실행 — 턴 < 0 이면 EVENT00, 아니면 저장된 스테이지 파일. 헤더의 BGM > 0 이면 재생.
- 새 게임: 유닛·마을 블록 0, 소지금 200, 맵 해제, `EVENT00 begin`, 턴 −1.
- 자동 저장: `BATTLE_START` 가 슬롯 30 (`event_script_format.md` op 35), 턴 종료 처리가 슬롯 31 (`story_flow.md` §4).
- 스크립트 플래그는 **u16 24개**(헤더 +40)다. 코퍼스가 쓰는 인덱스는 0~4, 10 (최대 10).

## 2. 소리

### 2.1 음악 `MUSIC n` [관찰 `FUN_0042e8c0`]

`midi\bgm%02d.mid`(GM) 또는 `_gs.mid`(INI `MusicDevice` == 2 이고 n ∉ {0, 3, 21, 24} 일 때) 를 `FUN_00436480(n+2, path, gs)` 로 재생(MCI). n < 0 → 정지(`FUN_004364e0`). 현재 곡 `DAT_0044b758` 은 세이브 헤더 +106 에 기록된다. 파일: `bgm00..24` 25곡 × 2 (GM/GS), `back.lzh`(미사용 아카이브). 코퍼스 사용: MUSIC 227회, MUSIC_FADE 243회. `MUSIC_FADE a b` 는 `FUN_00436500(a, b)` 로 간다 [관찰 FUN_004085f0 @0x409150]: a = ms(0 이면 즉시, 아니면 `SetTimer(a/50)` 50단계), b = 방향(0 → 음량 0 뒤 정지, ≠0 → 최대). 따라서 코퍼스의 `(0, 2000)` 42회는 "즉시 최대 음량" 이다. `MUSIC n` 도 재생 뒤 `FUN_00436500(0, 1)` 로 음량을 되돌린다. 반복 재생 여부는 MCI 알림 처리(`FUN_00436480` 내부) 미분석 [추정: 반복].

### 2.2 효과음 `SOUND s` [관찰 `FUN_0040d950`]

`wave\%s.wav`, 채널 16개(`DAT_0044f1b8..f1f8`). 플래그 1(이름 앞 `*`) → 채널 0 고정(기존 채널 0 소리 정지), 아니면 첫 빈 채널(모두 차 있으면 0). 빈 이름 → 채널 0 정지. 1초 타이머(`SetTimer 9000+ch`)로 종료를 확인한다. 파일 107개. 코퍼스 사용: SOUND 378회.

## 3. 비주얼 씬 (모드 8) [관찰]

### 3.1 디스패치 `PLAY_VISUAL n` (`FUN_004082d0`, 테이블 0x449598 = (i16 scene, i16 step)[48])

| n | 장면 | 비고 |
|---|---|---|
| 0..17 | 0 (오프닝 무비), 시작 부 n | 오프닝은 18부(`FUN_00401c60` 의 case 0..0x11) |
| 21..33 | 1..13, 시작 부 0 | |
| 그 외 | (0, 0) | 테이블이 0 |

코퍼스 사용 12회: 0 ×2, 21, 23, 24, 26, 27, 29, 30, 31, 32, 33 → 장면 0, 1, 3, 4, 6, 7, 9, 10, 11, 12, 13 (장면 2, 5, 8 은 스크립트가 쓰지 않는다).

### 3.2 프레임 함수 `FUN_004016f0` (모드 8)

상태 `DAT_0044965c`: 0 → `FUN_00401790`(시작: 커서 숨김, 화면 준비) → 1 (재생: `FUN_00401b40` 이 0 을 돌려줄 때까지) → 2 → `FUN_00401b00`(정리: 상태 0, 커서 복원) → 0 반환 → 모드 4(스크립트) 복귀. `FUN_0041dd80`(= `DAT_0044a63c`) 이 0 이면 중단(사용자 취소 플래그 [추정]).

`FUN_00401b40` 은 장면 번호 `DAT_00449658` 로 장면 함수를 고른다: 0 `FUN_00401c60`, 1 `FUN_00405270`, 2 `FUN_00405420`, 3 `FUN_00405980`, 4 `FUN_00405c70`, 5 `FUN_00405e00`, 6 `FUN_00406050`, 7 `FUN_00406300`, 8 `FUN_004064d0`, 9 `FUN_00406650`, 10 `FUN_00406810`, 11 `FUN_00406a30`, 12 `FUN_00406d90`, 13 `FUN_00407440`. 각 장면 함수는 부(`DAT_00449660`)와 소단계(`DAT_00449664`)의 상태 기계이며 타이머(`FUN_004024f0(ms)`, `FUN_0041dbc0(ms)`), 페이드(`FUN_0041a890`, `FUN_0041a910`, `thunk_FUN_004184d0`), 그리기 원시(`FUN_00419c70` 블릿, `FUN_0041dd40` 채우기, `FUN_00419e40`, `FUN_004198d0`, `FUN_00419970`, `FUN_0041aac0`, `FUN_00419a20`)를 부른다. 예: 장면 1 = `FUN_004052a0`: 그리기(`FUN_00405340`) → 페이드 대기 + 3000 ms → 페이드 아웃 → 6000 ms → 끝.

### 3.3 이미지 목록 `DATA\vsllst.dat` (7470 B = 249 × 30 B) [관찰 `FUN_00401f70`]

| 오프셋 | 형 | 의미 |
|---|---|---|
| 0 | u16 | 장면 번호 (0..13) |
| 2 | u16 | 부(step) — 그 부가 시작될 때 로드 |
| 4 | u16 | 이미지 슬롯 (0..138, `FUN_004196a0(slot, path, a, b, c)`) |
| 6 | char[16] | 비트맵 이름 (`bmp\%s.bmp`; `NO_ENTRY` 는 건너뜀) |
| 22 | u16 | 로드됨 플래그 (실행 중) |
| 24, 26, 28 | u16 ×3 | 팔레트 재배치 인자 (`FUN_00434250(bmp, a, b, c)`, c ≠ 0 일 때; 예 122, 10, 112) |

`FUN_00401f70(step, max)` 가 현재 장면·부의 미로드 레코드를 `max` 개까지 로드한다. 640×480 보다 작은 이미지는 서피스로(`FUN_00419080`), 큰 이미지(예 `v01b` 1008×352 스크롤 배경)는 메모리 비트맵으로 둔다. 웹판 비트맵 228장(`v*`, `vop*`, `ved*`).

장면 함수(원시 함수 표, 장면별 상태 기계, 오프닝 표 시각)는 `analysis/visual_scenes.md` 에 정리했다.

## 4. 타이틀·다이얼로그 [관찰 일부]

타이틀 다이얼로그 0x9C(`LAB_00410370`), 슬롯 선택 0x8F(`LAB_004230b0`), 상점 `LAB_0040c4e0`, 장비 `LAB_0042e720`/`LAB_0042e2a0` 는 Win32 다이얼로그 리소스 프로시저로 Ghidra 가 함수로 잡지 못했다(미분석). 웹판은 HTML 오버레이로 대체한다.
