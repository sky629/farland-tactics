# 파랜드 택틱스 2 (FT2.exe) 데이터 파일 포맷

분석 대상: `FT2.exe` (PE32 x86, sha256 `979b0c7a…`, 1997-09-24 빌드, 제작 TGL, 한국 발매 소프트컴).
분석 도구: Ghidra 12.1.4 (REA 경유). 함수 주소는 FT2.exe 기준이다.
표기: **관찰** = 디컴파일 코드로 확인함. **추정** = 데이터 패턴으로 추론함.

## 1. 공통 사항

| 항목 | 내용 | 근거 |
|---|---|---|
| 압축 | `.bmp`, `.map` 전부 SZDD(MS COMPRESS.EXE, LZSS 4 KB 윈도) 압축. 게임은 `LZ32.DLL`(LZOpenFile/LZRead)로 투명하게 푼다. | `FUN_00418230`, `FUN_004180f0` |
| 경로 | 리소스 경로 포맷 테이블 `0x44c130` (20개). 예: `map\stage%02d.map`, `sprite\%s.apd`, `data\event%02d.dat`, `save\save%02d.dat`. | `FUN_004340c0` |
| 화면 | 640×480, 8bpp 팔레트, DirectDraw. 맵 이미지는 팔레트 10..121번을 32..143번으로 재배치해 쓴다. | `FUN_00410b20`, `FUN_00434250` |
| 이미지 | 모든 BMP는 무압축 8bpp. 투명색(색 키)은 대상마다 다르다. 스프라이트: 이미지 레코드의 `key` 바이트(249~255 혼용, APD v<2는 255). 맵 레이어: 시트 좌상단 픽셀 인덱스, 10~245이면 249로 대체. 배경: 불투명. "246 이상 투명" 같은 고정 규칙은 틀린다(키 255 이미지 500개 안에 246이 실제 색으로 있음). | `FUN_00428620`, `FUN_0040e0a0`, `FUN_00431460` |
| 문자열 | 데이터 안의 한글은 CP949. | item.dat 등 |
| 사운드 | `wave\*.wav`(mmio), `midi\bgm%02d.mid`, `bgm%02d_gs.mid`(GS 음원용), CD-DA 선택 가능. | import 목록 |

도구: `tools/ft2_szdd.py`(압축 해제·PNG 변환), `tools/ft2_map.py`, `tools/ft2_apd.py`, `tools/ft2_tables.py`.
모두 `python3 -I`로 실행한다.

## 2. 맵 `map\stageNN.map` (FM2) — 관찰

SZDD를 푼 뒤의 구조. 모두 리틀 엔디언.

| 오프셋 | 형식 | 의미 |
|---|---|---|
| 0x00 | `"FM2\0"` | 매직 |
| 0x04, 0x08 | u32 w, u32 h | 논리 격자 크기. 셀 수 = `w*h + (w-1)*(h-1)` |
| 0x0C | u32 n | 오브젝트 레이어 수 |
| 0x10 | char[16] | 배경 BMP 이름 (`map\`), 비어 있을 수 있음 |
| 0x20 | i32×2 | 미확인 (항상 1, 1) |
| 0x28, 0x2C | i32 c, i32 r | 시작 카메라/커서 셀 (×32, ×16 → 픽셀) |
| 0x30 | RECT(i32×4) | 뷰 영역(대각 셀 단위). 원점과 맵 픽셀 크기를 정한다 |
| 0x40 | char[16]×n | 레이어 BMP 이름 |
| 그다음 | u32×셀수 | 각 셀 레코드의 절대 오프셋 |

셀 레코드:

| 오프셋 | 형식 | 의미 |
|---|---|---|
| 0 | i16 height | 높이. 화면 y를 `height*8`만큼 올린다 |
| 2 | u8 blocked | 1이면 이동 불가 (`FUN_0041f340`) |
| 3 | u8 flag2 | 미확인. 0이 아니면 커서로 선택 불가 (`FUN_0042dda0`) |
| 4 | u8 land | 지형 종류(디버그 표시 "L:"). 값 0~5, 7 관찰. 의미 미확인 |
| 5 | u8 n_obj | 오브젝트 수 (0~6) |
| 6 | 14 B × n_obj | 오브젝트: u8 layer, u8 front, i16 left, top, right, bottom, i16 ox, i16 oy |

좌표계 (`FUN_0042d960`, `FUN_0042dd00`, `FUN_00431460`):

```
셀 주소 (c, r): 0 <= c, r < w + h - 1,  유효 조건: w-1 <= c+r <= w-1+2(h-1), |c-r| <= w-1
origin_x = (view.top - view.left) * 32
origin_y = -(view.top + view.left) * 16
screen_x = (c - r) * 32 + origin_x
screen_y = (c + r) * 16 + origin_y - height * 8
타일은 64×32 마름모, 높이 1단 = 8px
(screen_x, screen_y)는 마름모의 중심(앵커)이다. 64×32 바닥 타일은 (ox, oy) = (-32, -16)에 놓인다 (13,857/14,133개)
오브젝트는 (screen_x + ox, screen_y + oy)에 레이어 이미지의 RECT를 그린다
유닛 스프라이트도 같은 앵커에 놓인다 (FUN_00429c40 → FUN_0042dd50)
그리기 순서 (FUN_0042a990 → FUN_0042df70 → FUN_0042d1e0): 행 s = c + r 오름차순, 행마다
  [front == 0 오브젝트 전부] → [그 행의 스프라이트들] → [front != 0 오브젝트 전부]. 행 안의 셀은 c 오름차순
Shift 키 / EnablePermiation 옵션: front != 0 오브젝트를 체커보드(한 픽셀 걸러 투명)로 그린다 (mode 4)
```

검증: 76개 맵 전부 파싱 성공. 오브젝트 19,339개의 RECT가 모두 해당 레이어 BMP 범위 안에 있다.

## 3. 스프라이트 `sprite\*.apd` (APD v0~3) — 관찰

| 구간 | 크기 | 내용 |
|---|---|---|
| 헤더 | 16 B | `"3DPA"`(버전 3), u32 미사용, u16 시트 수, u16 이미지 수, u16 패턴 수, u16 애니 수 |
| 시트 | 256 B × n (v0: 1024 B) | BMP 파일명 |
| 이미지 | 20 B × n | u8 sheet, u8 key(색 키 팔레트 번호), u16 x, y, w, h, i16 ox, oy, 6 B 패딩. 반전 시 오프셋은 -(ox+w), -(oy+h) (`FUN_00428620`) |
| 패턴 | 520 B × n (v<3: 72 B) | u32 미사용(게임이 읽지 않음), i16 y_offset(그릴 때 y에서 뺌), u16 count, u16 image_index[count] (`FUN_00428780`, `FUN_0042a610`) |
| 애니 | 36 B × n | char name[32], u16 script_offset, u16 script_length |
| 스크립트 | 마지막 애니의 offset+length+1 | ASCII 애니메이션 스크립트 |

파일 끝의 나머지 바이트는 게임이 읽지 않는다(312개 중 107개에 남은 데이터가 있음).

애니메이션 스크립트 문법 (`FUN_00424c80`):

| 명령 | 의미 | 상태 |
|---|---|---|
| `S<ms>` | 이후 프레임의 표시 시간(ms). 기본 200 | 관찰 |
| `P<list>` | 목록 요소 `[A|B|C|D][(n)|(#n)][H|V]<패턴>[-<패턴>]`. 숫자마다 프레임 하나. `-`는 범위(양방향). `A`~`D`는 표식 1~4, `(n)`은 트리거 값을 **바로 다음 숫자**의 프레임에 붙인다(범위면 마지막 프레임). `H`/`V`는 숫자 바로 앞 1~2글자에 있을 때만 그 프레임을 반전한다(`FUN_00425100`). 숫자를 읽을 때마다 트리거·표식·범위 플래그가 초기화된다. 구분자(`,`, 공백)는 숫자 앞 `H`/`V` 비트만 지운다 | 관찰 (`FUN_004253a0`, `FUN_00424c80`) |
| `N<n>` | 이 스텝의 프레임 수를 n으로 맞춘다. 부족하면 순환해 채우고, 많으면 자른다 | 관찰 (`FUN_00425190`) |
| `M<dx>,<dy>` | 스텝 전체의 이동량(px). 두 번째 숫자에서 스텝을 끝낸다. 속도 = M / 총 시간(ms). `HM`은 dx, `VM`은 dy 부호 반전 | 관찰 (`FUN_00425520`) |
| `H`, `V` | 좌우/상하 반전. 숫자 앞(그 프레임), `P` 앞(목록 전체), `@` 앞(포함 전체). 비트 XOR로 합성 | 관찰 (`FUN_00425100`) |
| `@<name>` | 같은 파일의 다른 애니를 스텝 단위로 포함(이름은 `,`/공백까지). 원작은 현재 애니 뒤쪽에서만 찾는다 | 관찰 (`FUN_00425560`) |

트리거 `(n)`과 표식 `A`~`D`는 전투 코드가 `FUN_004294b0`, `FUN_00429380`으로 꺼내 쓴다(소비 의미 미확인).
P 없이 M만 있는 스텝은 직전 스텝의 프레임을 다시 쓴다. 예: `P21\r\nM4,2\r\nM-6,-3\r\nM3,2` = 피격 흔들림.
재생(`FUN_0042a210`): 틱마다 프레임을 최대 하나만 넘긴다. 스텝이 끝나면 M을 확정 오프셋에 더한다. 비반복 애니가 끝나면 오프셋은 0으로 돌아간다(플래그 0x40이면 유지).
애니 이름 규칙: `F.`(앞모습)/`B.`(뒷모습) + 동작 (`STAND`, `SET`, `DEFENSE`, `UP_DAMAGE`, `MIDDLE_DAMAGE`, `DOWN_DAMAGE`, `S/DAMAGE`, `A/DAMAGE`, `DEAD`, `FALL`, `LIFT`, `LEVITATE`, `COMPLETE`, `ATTACK1`, `ARROW1`, `EFFECT` …).

캐릭터 스프라이트: `sprite\char_%02d%c.apd` (문자 = 방향/변형), NPC는 `npc_*`, 효과는 이름 그대로(`burst`, `meteo`, `thunder` …).

## 5. 이벤트 스크립트 `data\event%02d.dat` — 관찰

심볼 테이블(`name\0` + u32 offset) 뒤에 바이트코드가 온다. 해석기는 `FUN_004085f0`, opcode 64개(0xff 접두).
라벨 이름은 실행 중에도 만든다: `battle%02d`, `WIN%02d`, `AFTER%02d`, `BEAT%02d`, `ASSIST%02d`, `levelup%02d`, `Town%02d`, `get%03d`, `magic%02d`, `%sPOP_%d`, `GAMEOVER`, `begin`, `Restart`.
상세 opcode 표는 `event_script_format.md`에 있다.

## 7. 유닛 구조체 (124 B, u16 단위) — 관찰

[0] id, [1] 종족, [2] 레벨, [4] c, [5] r, [8] 플래그, [9] 진영(0 아군, 7 특수), [0x12] HP최대, [0x13] HP, [0x14] MP최대, [0x15] MP, [0x16] 경험치 `=(레벨-1)*100`, [0x17] 공격, [0x18] 방어, [0x19] 지력, [0x1a] 마항, [0x1b] 민첩, [0x1c..0x1f] 몬스터 장비/드롭(추정), [0x2e..0x31] 방향·애니 상태, [0x34] AI 값 100, [0x38..0x3d] 상태이상(추정).
생성 시 종족 기본치를 넣고 `FUN_0041f7c0`를 (레벨-1)번 호출해 성장시킨다. 자세한 전투 공식은 `battle_rules.md`에 있다.

## 8. 이동·사거리 규칙 — 관찰 (`FUN_00439690`, `FUN_00439b40`, `FUN_0041f410`, `FUN_00438d70`)

이동 범위는 유닛 중심 21×21 창의 표(셀당 u16×2: [0] 남은 이동력, [1] 대상 종류)로 계산한다.

```
시작 셀 이동력 = 30 (고정)
셀 진입 비용   = race.cost_land[land]        (land = cell.land, 단 cell.flag2 != 0 이면 0; 유닛이 서 있으면 0)
                 cell.blocked != 0 → 99 (진입 불가), 99 = 그 지형 진입 불가
                 LEVITATE(상태 0xb) 상태면 land 0 셀도 cost_land1 비용으로 진입
                 상태 10(가속으로 추정)이면 비용 -1
높이 제한      = 오를 때 (new - cur) <= race.climb_max, 내려갈 때 (cur - new) <= race.drop_max
                 필드 모드에서 cost_land0 != 99(비행 종족) 또는 LEVITATE면 제한 없음
남은 이동력    = 현재 - 비용. 1 이상이면 진입 가능, 2 이상이면 계속 전진 (4방향 재귀)
ZOC            = 적(상태 1,3,4,5,8,9 제외, 높이차 < 8)에 인접한 셀에 들어가면 이동력 1로 고정 (멈춤)
적 판정        = 두 유닛의 진영(0=아군, 그 외 적, 7=중립 제외) 다름. 상태 7(CHARM)이면 반전
거리           = |Δc| + |Δr|,  방향 = 4방향(0~3)
```

사거리: 무기(item)의 `+0x2a..+0x2c`(min, max)와 종류 `+0x32`(1 = 직선 무기: 같은 행/열만, 3 = 높이 무시). 무기 종류 3이 아니면 높이차 4 초과 시 공격 불가. 마법은 `magic.target`(1 = 아군 대상)과 `magic.shape`(0/1/3 = 거리 min..max 범위, 2/5 = 4방향 직선, 4 = 맵 전체)로 대상 셀을 표시한다.

race.dat의 나머지 필드: idx 19 `climb_max`, idx 20 `drop_max`, idx 21~28 `cost_land0..7`(마법사: 99,5,5,6,7,7,8,5 → 평지 6칸 이동).
`land` 값: 0 = 지형 없음(진입 불가), 1~7 = 지형 종류(비용은 종족별).

## 9. 남은 미확인 사항

- `land` 1~7 각각의 이름(초원·숲·물 등)과 회피/방어 보정 여부.
- item.dat 필드 대부분과 magic.dat 숫자 필드 7개의 의미. 장비·사용 코드 분석이 필요하다.
- race.dat idx 0, 15~18, 29~32의 의미.
- 스프라이트 레코드 +0x48(같은 행 안의 그리기 순서 2차 키, `FUN_00429cb0`)의 출처.
- 애니 트리거 `(n)`과 표식 `A`~`D`의 소비 의미(효과음·타격 시점으로 추정).
- 팔레트 애니메이션(물 효과) 범위. INI 옵션 `DisablePaletteAnime`가 있다.
