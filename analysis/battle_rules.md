# Farland Tactics 2 (FT2.exe) 전투 규칙 분석

- 대상: `FT2.exe` (x86 PE, sha256 979b0c7a…), Ghidra 12.1.4 디컴파일.
- 표기: **[관찰]** = 디컴파일 코드에서 직접 확인(함수 주소 병기). **[추정]** = 데이터 값·호출 문맥에서 유추.
- 데이터 파일 경로: `DATA/race.dat`(74×86B), `DATA/item.dat`(180×56B), `DATA/magic.dat`(84×64B).
- 핵심 함수
  | 주소 | 역할 |
  |---|---|
  | `FUN_0043b4a0` | 행동 해석기: 대미지·회복·상태이상·아이템 효과 계산 (타깃 1명당 1회 호출) |
  | `FUN_0043afd0` | 행동 실행: 대시 판정 → 타깃별 `0043b4a0` → 연출 → 이동/행동 플래그 |
  | `FUN_00438d70` | 타깃 목록 생성 (무기 종류·마법 범위 타입) |
  | `FUN_00439690` | 사거리 하이라이트 (공격·아이템·마법 사정거리) |
  | `FUN_0043dd90` | 명중/회피/크리티컬/무기효과 확률 판정 (민첩 기반) |
  | `FUN_0043df50` | 상태이상 마법 성공 판정 (지혜+민첩 vs 마항+민첩) |
  | `FUN_0043a2e0` | 결과 처리: 사망, 경험치, 레벨업, 상태이상 적용, 승패 판정 |

## 1. 공통 정의

```text
rand(n)          = FUN_004337a0(n)  → 0 .. n-1 (균등)                          [관찰 0x4337a0]
items(u)         = u[0xa](무기), u[0xb](방어구), u[0xc], u[0xd](장신구)           [관찰 0x438d70, 0x43b4a0]
dir(a→b)         = |dx|>|dy| ? (dx>0 ? 1 : 2) : (dy>=0 ? 0 : 3)                 [관찰 0x41f4d0]
                   0=+y, 1=+x, 2=-x, 3=-y,  반대방향 = dir ^ 3
dist(a,b)        = |dx| + |dy| (맨해튼)                                           [관찰 0x41f2e0]
hostile(a,b)     = a≠b, 양쪽 side≠7, 양쪽 side≠1, (a.side==0) ≠ (b.side==0), 단 a가 CHARM(7)이면 반전
                                                                                  [관찰 0x41f520]
incap(s)         = s ∈ {1(사망),3(수면),4(석화),5(동결),8(홀드),9(은신)}           [관찰 0x43dd90 등]
statusOK(t)      = (t.side==0 || t.id==8)   ← 이름 있는 적 캐릭터(id≠8, id<0x1e)는 상태이상 면역
                                                                                  [관찰 0x43b4a0 각 case]
```

속성 3축 (race +0x32/+0x34/+0x36, item +0x24/+0x26/+0x28, 마법 +0x18/+0x1a/+0x1c, 유닛 [0x2b..0x2d]):

| 축 | 양(+) | 음(−) | 근거 |
|---|---|---|---|
| 0 | 불 (프레임버스트 +5, 플레임소드 +15) | 얼음 (프리즈 −5, 아이스블레이드 −15) | [추정] magic/item 데이터 |
| 1 | 바람·번개 (라이트닝 +10, 썬더블레이드 +15) | 대지 (스톤엣지 −5, 메테오 −20) | [추정] |
| 2 | 신성 (힐링 +1, 엔젤 +10) | 암흑 (다크포스 −15, 고스트 −20) | [추정] |

## 2. 물리 공격 (action 0) — `FUN_0043b4a0` 하단 + `FUN_0043afd0`

### 2.1 명중/회피/크리티컬 [관찰 0x43b4a0 L~780-800, 0x43dd90]

```text
agiTot(u) = u.agi + Σ items(u).agi(+0x22) + u[0x2a](민첩버프)

roll(a, b, base):                               # FUN_0043dd90(a,b,base)
  m = max(base,1)
  if incap(b.status): m *= 3
  elif a.facing == b.facing: m *= 2             # b가 a와 같은 방향 → 뒤를 보임
  elif b.facing != (a.facing ^ 3): m += m/2     # 옆
  chance = max(agiTot(a) * m / max(agiTot(b),1), 1)   # 단위 %
  return rand(100) < chance

순서:
  1. 타깃이 수면(3)이면 깨움: t.status = 0  (이후 판정은 깬 상태로)
  2. 크리티컬: att[0x32]==0 and roll(att, tgt, 3) → crit=1           (대시 공격이면 처음부터 crit=1)
  3. 회피:    att[0x32]==0 and !incap(tgt) and roll(tgt, att, 3) → MISS
              → crit=0, hit=0, 팝업 "miss!", 타깃이 공격자 쪽으로 돌아섬(t.facing = dir(t→att))
```
- 기본 크리티컬 3%, 회피 3% × 민첩비 × 방향 보정. 회피 roll은 인수가 (tgt, att)로 뒤바뀌어 호출되므로 **뒤에서 맞는 타깃이 오히려 회피 ×2** 보정을 받는다 [관찰, 원작 특이점].
- 마법·아이템에는 명중/회피 판정이 없다 [관찰: 0x43b4a0의 action≠0 경로에 roll 호출 없음].

### 2.2 대미지 [관찰 0x43b4a0 L~690-700, 900-1030]

```text
atk  = att.str + item[0xa].atk + item[0xc].atk + item[0xd].atk + att[0x26]      # 방어구(0xb)의 atk는 무시
def  = tgt.def + item[0xb].def + item[0xc].def + item[0xd].def + tgt[0x27]      # 무기(0xa)의 def는 무시
base = max(atk - def, 1)                                     # 디버그 "\t%s(str:%d)->%s(def:%d)"

# 속성 보정: 축 i=0..2 중 |A_i(att) - A_i(tgt)| 가 최대인 축 하나만 적용
#   조건: A_i(att)≠0, A_i(tgt)≠0, 그리고 sign(A_i(att)) 가 race.e_i 또는 무기.e_i 의 부호와 같을 것
if 선택축 존재:
  A = A_sel(att), D = A_sel(tgt)
  if sign(A)==sign(D): pct = -((|D| - |A| + 100) / 4)        # "동속성으로 %d%%다운!"  (예: A=D → -25%)
  else:                pct =  |D - A| / 2                     # "반속성으로 %d%%업!"
  base = max((100 + pct) * base / 100, 1)

# 물리 전용 배율 (정수 %)
mult = 100
if att[0x32] != 0: mult = 300                                 # 특수기(마카블댄스/멸신난무/데스모멘트) 플래그
if crit:           mult += 80                                 # "크리티컬!"
d = dir(att→tgt)
if tgt.facing == d:            mult += 25                     # 배후
elif tgt.facing != (d ^ 3):    mult += 15                     # 측면 (정면은 +0)
mult += (height(att) - height(tgt)) * 2                       # 타일 높이차 1당 ±2%  (FUN_0042cd50 첫 short)
dmg = max(mult * base / 100, 1)                               # "\t대미지%d%%!"

dmg = min(dmg, tgt.HPcur);  tgt.HPcur -= dmg;  if tgt.HPcur==0: tgt.status = 1(사망)
```
- 난수 폭 없음: 대미지는 결정적이고 난수는 명중/크리/회피에만 쓰인다 [관찰].
- 대시 공격 [관찰 0x43afd0]: 아군(side 0)이 `[0x32]==0` 상태에서 **같은 방향으로 3칸 이상 직진** 후 그 방향으로 공격, 경로 각 칸 높이차 ≤2, 비행 상태 아님 → crit=1 (+80%). 활(무기타입 3)은 타깃이 인접(dist 1)해야 대시 가능.
- 반격(카운터) 코드는 없다 [관찰: 0x43afd0 → 0x43b4a0 → 0x43a2e0 흐름에 반격 분기 없음].

### 2.3 무기 특수효과 (상태이상 부여) [관찰 0x43b4a0 L~796-830, 0x43a2e0 case 9]

```text
st = item[att.0xa].status(+0x34)
if st != 0 and statusOK(tgt) and roll(att, tgt, 20):          # 기본 20% × 민첩비
  st ∈ {2,3,6,7}: !incap(tgt) 이면 적용
  st ∈ {4,5}:     tgt.status ∉ {1,4,5,9} 이면 적용 (수면·홀드 중에도 적용)
  st == 8:        tgt.status ∉ {1,4,5,8,9} 이면 적용
  → 연출 후 tgt.status = st  (단, 사망 시 미적용; 지속 카운터 [0x34]는 갱신하지 않음)
```
무기 데이터: 포이즌다가·독손톱 2(독), 도림나이프·꿈꾸는지팡이 3(수면), 과묵한지팡이·마인장갑 6(침묵), 장난감/친구지팡이·로얄글로브 7(매혹), 스탠글로브·박염지팡이·마비손톱 8(마비). 11은 비행(패시브), 10·12는 효과 코드 없음 [관찰+데이터].

### 2.4 무기 사거리·공격 형태 [관찰 0x438d70, 0x439690]

| item +0x32 (무기타입) | 형태 | 비고 |
|---|---|---|
| 0 | 단일 타깃, 거리 `[+0x2a, +0x2c]` | 검·너클·단검·지팡이·손톱 |
| 1 | **직선 관통**: 바라보는 방향 1..+0x2c 칸 중 ≥+0x2a 인 모든 칸 | 파이크·체인위프·비지 등 (0x2a=1, 0x2c=2 → 2칸) |
| 2 | **T자 3칸**: 정면·좌·우 인접칸 (`DAT_0044c4b8` 방향표) | 하루바드·바루키리아 |
| 3 | 단일 타깃, 거리 1..7, `ARROW%d` 연출, 궤적 계산(FUN_00412ba0) | 적활A~E (0x2c=7) |

- 근접(타입≠3)은 공격자-타깃 높이차 `|Δh| > 4` 이면 타깃 불가; 활은 높이 제한 없음 [관찰 0x439690, 0x438d70].
- 아이템 사용 범위: 아군 유닛 중 거리 `[+0x2a, +0x2c]` = 0..1 (자신 또는 인접) [관찰 0x439690].

### 3.2 범위 타입 (+0x32) [관찰 0x438d70 + 0x439690]

### 3.3 마법 대미지 [관찰 0x43b4a0 L~870-1000]

```text
if magic.mp(0x16) > 0:
  atk = att.wis + Σ items(att).wis(+0x1e) + att[0x28]
  def = tgt.mgr + Σ items(tgt).mgr(+0x20) + tgt[0x29]        # "\t%s(wis:%d)->%s(mgr:%d)"
else:  (물리형 스킬; 현 데이터에서는 자기버프로 조기 return 되어 미사용)
  atk/def = 물리 공식과 동일
base = max(power + atk - def, 1)
속성 보정 = 물리와 동일 (부호 검사는 race.e_i 또는 magic.e_i)
dmg = min(base, tgt.HPcur); tgt.HPcur -= dmg; 0이면 사망
```
- 방향·높이·크리티컬·회피 **없음**. 난수 없음.
- 대미지+상태이상 마법(플래시, 프리즈, 블리자드, 썬더드래곤, 가스크레우드, 페트로크라우드, 다크포스, 브레스류 등)은 상태 판정 후 대미지도 반드시 적용.
- 화염계(1 프레임버스트, 9 이프리타, 71 화염브레스)는 타깃의 동결(5)을 먼저 해제 [관찰 case 1/9/0x47].

### 3.5 상태이상 마법 판정 [관찰 0x43df50 + 각 case]

```text
res(t) = t.mgr + t.agi + Σ items(t).mgr + Σ items(t).agi + t[0x29] + t[0x2a]     (0이면 1)
pow(a) = a.wis + a.agi + Σ items(a).wis + Σ items(a).agi + a[0x28] + a[0x2a]
bonus  = K + s·(A_axis(att) − A_axis(tgt)),  s = 마법 속성값의 부호, bonus = max(bonus,1)
m      = incap(tgt) ? 3 : 같은방향 ? 2 : 측면 ? 1.5 : 1
chance = max(pow(a) * bonus * m / res(t), 1) %      → rand(100) < chance 이면 성공
성공 시: tgt[0x34..35] = 100 (지속 카운터), tgt.status = 효과
```

## 5. 경험치·레벨업

### 5.1 경험치 [관찰 0x43a2e0 case 7, 8]

```text
행동 유닛이 아군(side 0)일 때만. k = 7
for 타깃 t, 결과값 v (양수=대미지, 음수=회복, ≥90000=메시지):
  if t.side == 0 or v ≥ 90000:           # 아군 대상, 또는 버프/치료/miss 등
      gain = max(k,1); k = max(k/2,1)    # 7, 3, 1, 1 …
  else:
      base = race[t.race].exp(+0x14)     # 보통 10, 몬스터 14~30, 세라프 150/200
      gain = base * v / t.HPmax          # 입힌 대미지 비율
      if t.HPcur == 0: gain += base      # 처치 보너스
      if t.id != 8:    gain *= 2         # 이름 있는 적 ×2
      pct  = max(100 + 20*(t.level - att.level), 10)   # ((Lt-La)*4+20)*5, 하한 10
      gain = max(pct * gain / 100, 1)
      if t 가 파티 슬롯(0~9) 유닛: gain = 0
  total += gain
exp += total (연출: 틱당 max(total/100,1)), exp 상한 9899
```

### 5.2 레벨업 [관찰 0x43a2e0 case 8/9, 0x41fae0]

```text
레벨 L 필요 누적 exp = (L-1)*100  → level = exp/100 + 1, 최대 99 (exp cap 9899)
생성 시 exp = (level-1)*100
레벨업마다 FUN_0041f7c0(unit, randomize=1, announce=1) 호출 후 이벤트 "levelup%02d"
```

### 5.3 성장 루틴 `FUN_0041f7c0(unit, randomize, announce)` [관찰]

```text
for stat in (HP,MP,str,def,wis,mgr,agi):           # race +0x18,+0x1c,+0x20,+0x24,+0x28,+0x2c,+0x30 = 레벨당 성장치
  g = race.growth[stat]
  if randomize: g += rand(3) - 1                  # -1..+1  (※ 상한검사용 난수와 적용 난수를 따로 뽑음)
  stat = (stat + g < 1000) ? stat + g : 999
if status != 1: HPcur = HPmax, MPcur = MPmax
if side == 0: [0x1c..] = { m | magic[m].mask & 1<<(id-1), 0 < magic[m].lv ≤ level }  (습득 주문 재구성)
              announce && magic[m].lv == level 이면 신규 습득 메시지
```
- 생성 시: `randomize = (side != 0)` → **적만 랜덤 성장, 아군은 결정적** [관찰 0x41fae0].
- 전투 중 레벨업: `randomize = 1` → **아군도 ±1 랜덤** [관찰 0x43a2e0 case 9].
- `hp_up!`…`agr_up!` 팝업은 레벨업이 아니라 영구 스탯 아이템(155~160)과 버프 마법의 표시다. `miss!`=90006, `well`(상태회복)=90007, `fly_high!`=90010, `landing!`=90011, 90000 = 무음 성공 [관찰 0x439f40, 0x43b4a0].

## 8. 미확인·주의 사항

- 유닛 [0x10],[0x11]: 용도 미확인. 주문 목록 길이 10은 추정.
- `ATTACK%d`의 `%d`는 전역 `DAT_0044a2a4`에서 오며(0x4163f0) 무기 필드와의 대응은 미확인 (0x416730 디컴파일 실패).
- 천사소환(82)의 소환 로직, 범위타입 5 사용처, 아이템 +0x34 = 10/12 의 패시브 의미는 미확인.
- 플레이어 페이즈 종료 시 적 유닛 상태 틱(`FUN_0043e1a0(0)`) 호출 위치는 직접 확인하지 못함(추정).
- 원작 특이점(재현 시 결정 필요): 회피 roll의 인수 역전(§2.1), 홀드(51)의 축 불일치(§3.5), 무기 상태이상의 카운터 미갱신(§2.3), 수면 타깃이 물리 공격 전에 깨어나 정상 회피 판정을 받음(§2.1), 적 유닛을 회복하면 음수 EXP가 1로 보정됨(§5.1).
