01 · 게임 정체와 기술

이 게임은 TGL의 Farland Saga다

리소스의 버전 정보는 CompanyName (주)TGL, ProductName (주)TGL FT2, 원본 파일명 FS.exe다. 데이터 안에는 welcome to farlandsaga, 스탭롤 텍스트에는 "파랜드 택틱스 ~시간의 이정표~"가 있다. 즉 한국판 "파랜드 택틱스 2"는 TGL의 Farland Saga: 時の道標(1998) 로컬라이즈판이다. 설치 레지스트리 키는 Software\SOFCOMSOFT\INSTALL(소프트컴)이다.

항목내용근거
실행 환경Win32 PE32 x86, 1997-09-24 빌드, CRT 정적 링크PE 헤더, 리소스 타임스탬프
화면640×480, 8bpp 팔레트, DirectDraw(전체 화면/창 모드), 맵은 640×480 청크 서피스로 합성FUN_00410b20, FUN_00431460
파일 I/O모든 BMP·MAP은 SZDD(MS COMPRESS) 압축. LZ32.DLL로 투명 해제FUN_00418230, LZ32 import 4개
사운드WAV(mmio), MIDI 스트림(GM/GS 두 벌), CD-DA 선택. DirectSoundWINMM import 25개
UIWin32 다이얼로그 21개(유닛 일람, 환경설정, 상점, 경험치 배분…), 메뉴, 디버그 메뉴(무적·부자·강제 클리어)RT_DIALOG/RT_MENU 리소스

표기 규칙: 관찰 디컴파일 코드로 확인 · 추정 데이터 패턴에서 추론 · 서브에이전트 별도 분석 문서에서 가져옴.

02 · 자산 인벤토리와 변환 파이프라인

리소스 경로 20개가 게임의 모든 파일을 설명한다

03 · 맵 포맷과 좌표계

마름모 격자 위에 그려진 그림 한 장

맵은 "미리 그려진 배경 그림 + 셀 메타데이터 + 셀에 붙은 오브젝트 조각"이다. 셀 수는 w·h + (w−1)(h−1)로, 엇갈린 마름모 격자다. 타일은 64×32px, 높이 1단은 8px다. 관찰

셀 레코드 (6 B + 14 B × n)

필드의미
i16 height높이. 등반·낙하 제한과 사거리 높이차에 쓰인다
u8 blocked1 = 진입 불가(비용 99)
u8 flag21 = 커서 선택 불가, 지형 0으로 취급. 맵 바깥 영역
u8 land지형 0~7. 0 = 지형 없음(진입 불가), 1~7은 종족별 이동 비용
u8 n_obj오브젝트 수(0~6)
오브젝트u8 layer, u8 front, RECT(i16×4), i16 ox, i16 oy — 레이어 BMP의 사각형을 (x+ox, y+oy)에 그림. front=1이면 유닛을 가림

이동 범위 규칙 관찰

시작 이동력 = 30 (고정)                           FUN_00439690
진입 비용   = race.cost_land[cell.land]  (blocked → 99, flag2 → land 0 취급)   FUN_0041f410
            LEVITATE(상태 0xb)면 land 0 셀도 cost_land1로 진입, 상태 10이면 비용 −1
높이 제한   = 오름 ≤ race.climb_max, 내림 ≤ race.drop_max  (비행 종족·LEVITATE는 무제한)
남은 이동력 = 현재 − 비용. ≥1 진입 가능, ≥2 계속 전진 (4방향 재귀)   FUN_00439b40
ZOC         = 적 인접 셀에 들어가면 이동력 1로 고정                FUN_00439dc0
거리        = |Δc| + |Δr|,   공격 높이차 > 4 이면 공격 불가(무기 종류 3 제외)

예: 마법사의 cost_land는 (99, 5, 5, 6, 7, 7, 8, 5)다. 평지(land 1)에서 6칸을 간다. 검사는 비용 4로 7칸이다. "이동력"이라는 수치는 따로 없고, 종족별 지형 비용표가 이동 거리를 결정한다.

04 · 스프라이트 포맷 (APD)

이미지 조각 → 패턴 → 텍스트 스크립트

APD는 3층 구조다. 시트 BMP에서 잘라낸 이미지, 이미지를 겹친 패턴(한 프레임), 패턴을 시간순으로 재생하는 애니메이션이다. 애니메이션은 사람이 읽는 작은 스크립트로 저장돼 있다. 관찰

구간크기내용
헤더16 B"3DPA", u32, u16 시트 수, 이미지 수, 패턴 수, 애니 수
시트256 B × nBMP 파일명
이미지20 B × nu8 sheet, u8 flag, u16 x y w h, i16 ox oy, 6 B 패딩
패턴520 B × nu32, u16, u16 count, u16 image[count]
애니36 B × nchar name[32], u16 offset, u16 length
스크립트가변ASCII, 끝의 잔여 바이트는 게임이 읽지 않음
명령의미
S<ms>이후 프레임 시간(ms). 기본 200
P<a>[-<b>][,…]패턴 범위를 프레임으로 추가. HP/VP는 반전
N<n>스텝 총 프레임 수(모자라면 순환)
M<dx>,<dy>스텝 이동량(px), 스텝 종료. 속도 = M / 총 시간
(n) (#n)이후 프레임의 트리거 값 추정
@name다른 애니 포함
F.STAND      S200 P1-3,2                 ← 앞모습 대기: 패턴 1,2,3,2를 200ms씩 반복
F.DEFENSE    S200 P0, S400 P4            ← 방어
B.S/DAMAGE   P21  M4,2  M-6,-3  M3,2  M-1,-1  M0,0   ← 피격 흔들림: M마다 스텝, 패턴 21 재사용
F.LIFT       S50 P6 N8 M0,-8  S50 P6 N8 M0,-16 … M0,-512   ← 상승(이동량 2배씩)

애니 이름은 F.(앞)/B.(뒤) + 동작이다. 전투 코드는 ATTACK%d, ARROW%d, DEFENSE, UP/MIDDLE/DOWN_DAMAGE, DEAD 같은 이름으로 애니를 찾는다. 마법 효과는 magic.dat의 효과 이름(BURST, HEAT, EXPLODE…)으로 효과 APD를 찾는다.

05 · 데이터 테이블

종족 74, 아이템 180, 마법 84

로더 FUN_0041eab0가 레코드 크기를 정한다. "종족"은 사실 직업과 몬스터 종류를 합친 개념이다. 0~6은 플레이어 직업(마법사, 검사, 치유의 손, 샤먼, 세이렌, 헌터, 정령사), 7은 NPC, 8부터는 보물상자·금·슬라임 같은 오브젝트와 몬스터다. 코드도 id ≥ 8을 몬스터로 구분한다.

파일레코드해독된 필드
race.dat86 B × 74이름[20], HP/MP/공격/방어/지력/마항/민첩 기본치와 레벨당 성장치(쌍), climb_max, drop_max, cost_land0..7, 몬스터 장비 추정
item.dat56 B × 180이름[20], 가격, 사거리 min/max(+0x2a/+0x2c), 무기 종류(+0x32: 1 직선, 3 높이 무시). 나머지 미확인
magic.dat64 B × 84이름[20], 숫자 7개(min/max 사거리 포함), 효과 APD 이름, 대상(1=아군), 형태(0/1/3 범위, 2/5 직선, 4 전체), 짧은 설명
*com.dat가변u32 offset[256] + CP949 설명문
STAGE%03d.dat28 B × n유닛 id, 종족, 레벨, i32 c, i32 r, 진영, 기타 4개

유닛 구조체 (124 B, u16 단위) 관찰

[0] id · [1] 종족 · [2] 레벨 · [4] c · [6] r · [8] 상태(1 사망, 7 매혹, 0xb 부양…) · [9] 진영(0 아군, 7 중립) · [0x12/0x13] HP 최대/현재 · [0x14/0x15] MP · [0x16] 경험치 = (레벨−1)·100 · [0x17~0x1b] 공격·방어·지력·마항·민첩 · [0x1c~0x1f] 몬스터 장비 · [0x2e~0x31] 방향·애니 · [0x38~0x3d] 상태이상. 유닛 50슬롯(0~9 아군, 10~49 스테이지), 생성 시 종족 기본치에 FUN_0041f7c0를 (레벨−1)번 적용한다.

06 · 이벤트 스크립트

라벨 테이블 + 0xFF 접두 바이트코드

data\event%02d.dat 20개가 스토리·마을·전투 흐름을 모두 담는다. 해석기는 FUN_004085f0, opcode 64개다. 게임 코드는 battle%02d, WIN%02d, levelup%02d, Town%02d 같은 라벨을 실행 중에 만들어 점프한다. 새 게임은 event00:begin, 불러오기는 저장된 이벤트의 Restart 라벨에서 시작한다. 관찰

인코딩 서브에이전트

요소형식
명령FF op 2바이트. 0xFF가 아니면 스크립트 종료
숫자i8 1바이트. 첫 바이트가 0x80이면 뒤에 i32 LE
유닛 참조숫자. 24 = 현재 전투 대상, 그 외 유닛 id

라벨문자열. 심볼 테이블을 대소문자 무시로 검색
심볼 테이블name\0 + u32 offset 반복, 0xFF 바이트로 끝

07 · 전투 규칙

공격력 대 방어력, 지력 대 마항력

전투 시퀀서 FUN_0043b4a0(10 KB, 90분기)에는 디버그 출력 %s(str:%d)->%s(def:%d)와 %s(wis:%d)->%s(mgr:%d)가 남아 있다. 물리는 공격력 대 방어력, 마법은 지력 대 마항력이다. 레벨업 메시지 hp_up!…agr_up!, miss!는 FUN_00439f40에 있다.

물리 공격 서브에이전트 관찰

agiTot(u) = agi + Σ장비.agi + 민첩버프[0x2a]
roll(a, b, base): m = base; b가 행동불능이면 ×3; 같은 방향이면 ×2; b의 옆이면 ×1.5
                  chance% = agiTot(a)·m / agiTot(b) (최소 1);  rand(100) < chance
crit = 대시 공격 || roll(att, tgt, 3)          # 대시: 3칸 이상 직진 후 그 방향으로 공격(높이차 ≤ 2)
miss = !행동불능(tgt) && roll(tgt, att, 3)     # 원작 특이점: 인수가 뒤집혀 "뒤에서 맞는 쪽"의 회피가 ×2
atk  = str + 무기.atk + 장신구.atk ×2 + 공격버프[0x26]
def  = def + 방어구.def + 장신구.def ×2 + 방어버프[0x27]
base = max(atk − def, 1)
속성: 3축(불/얼음, 풍뇌/대지, 신성/암흑) 중 |A−D|가 가장 큰 축 하나
      같은 부호: pct = −((|D| − |A| + 100) / 4)   (A = D → −25%)
      다른 부호: pct = |D − A| / 2
      base = max((100 + pct)·base / 100, 1)
mult = 100 (특수기 ×3 플래그면 300) + 80·crit + 25(배후) 또는 15(측면) + 2·(h_att − h_tgt)
dmg  = max(mult·base / 100, 1), HP에서 차감. 난수 대미지 폭 없음, 반격 없음.

마법

MP −= |magic.mp_cost|
atk  = wis + Σ장비.wis + 지력버프
def  = tgt.mgr + Σ장비.mgr + 마항버프
power = 속성 위력(elem0..2 중 첫 0 아닌 값)
base = max(power + atk − def, 1), 속성 보정 동일
명중·회피·방향·높이 보정 없음
회복: heal = min(wisTot, 결손)
리잘렉션: 사망자만, HP = min(wisTot/2, 최대)
흡수: 대미지 후 시전자 HP += min(첫 대상 대미지, 결손)

상태 마법 성공률: chance% = pow·bonus·m / res. pow는 시전자의 지력+민첩(장비·버프 포함), res는 대상의 마항+민첩. bonus는 마법별 기본값(석화 20, 수면·홀드·동결 30, 침묵·독 40, 매혹 50, 오더 60)에 속성 차를 더한다.

경험치와 성장

아군 행동만 경험치. 대상마다:
  gain = race.exp_value · dmg / HPmax
  처치 시 + race.exp_value, 일반 몬스터(id 8)가 아니면 ×2
  × max(100 + 20·(L_tgt − L_att), 10)%,  최소 1
  아군 대상(회복 등): 7, 3, 1, 1 … 고정
exp 상한 9899,  level = exp/100 + 1, 최대 99
레벨업: stat += race.*_up (랜덤이면 ±1), 상한 999
        생존 시 HP/MP 전회복. 생성 시 적만 랜덤 성장

턴: 플레이어 페이즈 → 적 AI 페이즈 → 상태 틱 → 라운드 리셋(이동·행동 플래그 초기화, MP += ⌈MPmax/10⌉, 버프 −1). 스테이지 시작 시 HP = 최대, MP = 최대/2. 독은 HPmax/10 + 1 피해. 수면 15, 동결 10, 침묵 15, 매혹 10, 홀드 10, 부양 20 카운터 후 확률 회복.

09 · 웹 리메이크 계획

자산은 그대로 쓰고, 엔진만 새로 쓴다

원본은 데이터 주도형이다. 그림·애니·맵·테이블·스크립트가 전부 파일에 있으므로, 웹 엔진은 "포맷을 읽고 규칙대로 돌리는 해석기"만 만들면 된다. 권장 구성은 TypeScript + Canvas 2D(또는 PixiJS)다. 640×480 정수 배율 렌더링이면 픽셀 아트가 선명하다.

  1. 자산 변환 파이프라인SZDD → PNG(투명 인덱스 ≥ 246), APD → 아틀라스 JSON, FM2 → 맵 JSON, DAT → JSON, WAV → OGG, MIDI → SoundFont 렌더 OGG. 이미 있는 Python 도구에 출력 단계만 붙이면 된다.
  2. 맵 뷰어배경 + 셀 오브젝트 2패스 + 격자 디버그 오버레이. 좌표식과 깊이 정렬(c+r 순)은 이 보고서의 공식 그대로. 성공 기준: 76개 맵이 원본 캡처와 같게 보인다.
  3. 스프라이트 애니메이터APD 스크립트(S/P/N/M/@/H/V) 재생기. 성공 기준: 312개 파일의 모든 애니가 끊김 없이 돈다.
  4. 필드 모드커서·이동 범위(비용표·높이·ZOC)·공격 범위·메뉴. 유닛 구조체와 종족 테이블을 그대로 쓴다.
  5. 전투와 성장battle_rules.md의 공식으로 피해·명중·경험치·레벨업 구현. 원본 세이브로 수치 검증.
  6. 이벤트 스크립트 VMopcode 64개 해석기. 대사 창·서식 명령·얼굴 그래픽·비주얼 신 포함. 성공 기준: event00:begin부터 엔딩까지 진행.
  7. 세이브·사운드·UIlocalStorage 세이브(원본 포맷 가져오기 선택), 다이얼로그 21개의 웹 UI 재구성.

주의할 점. 그래픽·음악·시나리오의 저작권은 TGL(및 소프트컴)에 있다. 변환한 자산을 배포하지 말고, 사용자가 자기 원본 파일을 브라우저에서 직접 변환해 쓰는 구조(파일 드롭 → 로컬 변환)가 안전하다.

한글 폰트: 원본은 Windows 굴림/명조 계열 비트맵을 그렸다. 웹에서는 비슷한 픽셀 폰트(예: Galmuri)로 대체하거나 CP949 텍스트를 미리 렌더해 둔다.
